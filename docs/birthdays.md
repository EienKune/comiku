# 角色生日

生日模块为可选功能，独立于作者、候选和作品流程。内置 SchaleDB 来源；关闭时不请求来源，也不启动生日 worker 轮询。API 与 worker 均设置 `BIRTHDAYS_ENABLED=true` 后，管理员可在系统管理的生日页配置工作台展示、提醒时间和提前天数。

## 展示与资料

工作台在统计上方展示未来七天（含今天）的生日；没有近期生日时显示最近日期，同一天的角色全部保留。完整名册按需加载，可搜索姓名与别名。未知生日单独列出，不猜测日期。头像使用原皮的 SchaleDB 图片；加载失败时使用姓名首字作为头像。

所有日程按 `Asia/Shanghai` 计算。来源读取 config、日文和中文三份 JSON，仅纳入日服已发布角色。人物身份使用已审核的稳定映射，换装合并至同一人物；原皮的中文全名与历史名字保留为检索信息。未知身份或冲突不自动合并进提醒。开发者可通过 `BirthdayIdentity` 审核新条目，`BirthdayNameOverride` 保存显示名和别名覆盖；页面暂不提供这两项技术编辑。

首次发现且中文名字尚未翻译的新人物会以 `unlocalized` 暂存，暂不展示、不猜译名；后续中文资料完整时可恢复。暂存人物仍保留稳定身份和全部关联条目，关联边消失不会重新编号。若发现跨人物关联或组内生日冲突，则转为 `pending` 等待人工确认，不因下一次来源变化自动恢复。已发布人物的中文资料异常仍拒绝整版更新，继续使用最近有效名册。

worker 在启动和每日 06:00 后登记持久同步任务。失败保留最近有效资料，任务先依照通用 Jobs 重试，之后每小时重新检查。正常成功后安排下一日检查。同一时刻最多一项生日资料任务，不占用 X/Pixiv 的采集槽。单份请求限制 20 秒、整体 60 秒和每份 8 MiB，只接受同来源 HTTPS 重定向。普通用户页面不展示同步故障提示；管理员可查看最近成功检查和资料更新时间，后台记录脱敏错误码。

资料快照按内容去重。每天最多清理 20 份超过 90 天且未被当前资料或提醒审计引用的旧快照；仍被提醒引用的资料不删除。

## 群提醒

群提醒还需启用现有通知配置，并在通知管理中订阅目标群的生日提醒。默认 09:00、生日当天，可另外选择提前 1 天或 7 天；群总开关仍有效。生日订阅和模板独立于作品订阅，修改生日设置不会改变作品消息的订阅代数或取消作品消息。

首次开启只接收开启之后到期的提醒，不自动补发历史日期。重启时仅恢复当前发送日内到期且尚未登记的摘要；每个发送日期与提前天数组合只登记一次，多个同日生日合并成一条消息。资料超过 48 小时未成功检查时暂停生成提醒；当天恢复有效资料后仍可补齐尚未登记的摘要。跨日不继续自动发送昨天的摘要。

消息在登记时冻结目标日期、完整姓名、群目标和提示语，沿用通知 Event → Delivery → Jobs → OneBot 投递链。模板修改不改写已登记消息。投递前复查生日全局、提前天数、群订阅和群总开关；关闭后重开不会复活旧代消息。结果未知的消息保持未知，不盲目重发；管理员确认后可使用现有历史补发操作，仍校验权限和当前订阅。

生日页的“检查资料”只登记资料任务，预览仅使用合成示例，不向真实群发送。普通测试使用合成 JSON、数据库 fixture 和替代 transport，不访问真实来源或群。
