# 角色生日

生日模块为可选功能，独立于作者、候选和作品流程。以 SchaleDB 为主源，Kivo 补充未实装且有生日资料的人物；关闭时不请求任何来源，也不启动生日 worker 轮询。API 与 worker 均设置 `BIRTHDAYS_ENABLED=true` 后，管理员在系统管理的角色生日页管理数据与工作台展示，在推送通知的“推送设置”中配置生日全局开关、提醒时间、提前天数及各群订阅。

## 展示与资料

工作台在统计上方展示未来七天（含今天）的生日；没有近期生日时显示最近日期，同一天的角色全部保留。完整名册按需加载，可搜索姓名与别名。未知生日单独列出，不猜测日期。SchaleDB 人物使用原皮头像，补充人物使用 Kivo 头像；加载失败时使用姓名首字。

所有日程按 `Asia/Shanghai` 计算。SchaleDB 读取 config、日文和中文三份 JSON，提供日服已发布角色；Kivo 未实装人物只要有可用生日和中文资料也可纳入，不按 NPC 标记过滤。人物身份使用稳定映射，换装合并至同一人物；中文全名与历史名字保留为检索信息。来源记录不等于逐项经过官方出处审定，有争议的日期应核对官方资料后处理。

来源 ID 与人物身份分开保存。既有 SchaleDB 人物沿用原 key；先收录的 Kivo 人物日后实装仍沿用原 key，只增加明确游戏 ID 的关联。只有确实存在于 SchaleDB 的正游戏 ID、明确的换装关系可以建立跨源桥，数字 0 和同名不能证明身份。确认后的关联不会因来源暂时漏掉关系而消失。首次出现的疑似同名人物可暂存，等明确 ID 后再解除重复展示保护；多个已发表身份、跨人物或生日冲突须开发者复核，不自动吞并身份或重写历史消息。

开发者通过 `BirthdayIdentity` 审核 SchaleDB 条目，`BirthdayExternalEntry` 保存 Kivo 最小资料缓存、已接受关联及待核对状态，`BirthdayNameOverride` 保存显示名和别名覆盖。技术编辑应在停止生日 worker 后按统一合并名册锁处理；页面不提供这些身份编辑。Kivo 使用[基沃托斯古书馆](https://kivo.wiki/)的公开资料，转载与第三方素材按其[使用条款](https://kivo.wiki/license)分别处理，资料不因本项目代码的 MIT 许可而改变许可。

首次发现且中文名字尚未翻译的新人物会以 `unlocalized` 暂存，暂不展示、不猜译名；后续中文资料完整时可恢复。暂存人物仍保留稳定身份和全部关联条目，关联边消失不会重新编号。若发现跨人物关联或组内生日冲突，则转为 `pending` 等待人工确认，不因下一次来源变化自动恢复。已发布人物的中文资料异常仍拒绝整版更新，继续使用最近有效名册。

已接受的生日资料发生冲突时，旧日期仍可展示，但该人物暂停生成新提醒；来源回滚不会自动解除待核对状态，明确复核后才恢复。尚未接受的新换装条目发生冲突，不影响已有可信人物的提醒。

worker 在启动和每日 06:00 后登记 SchaleDB 持久同步任务，成功后安排下一日检查。失败保留最近有效资料，任务按持久化的可执行时间等待 5 分钟再重试，保留每项任务最多三次尝试；耗尽后再等 5 分钟登记新任务，重启不跳过等待。同一时刻最多一项生日资料任务，不占用 X/Pixiv 的采集槽。单份请求限制 20 秒、整体 60 秒和每份 8 MiB，只接受同来源 HTTPS 重定向。普通用户页面不展示同步故障提示；管理员可查看最近成功检查和资料更新时间，后台记录脱敏错误码。

Kivo 索引每天完整检查，详情按独立到期时间分批更新：每批最多 20 条、总网络时间最多 45 秒，串行请求间隔 250 毫秒；索引限制 40 页、2000 条和每页 1 MiB，详情每份最多 8 MiB。首次建立名册会逐步补齐，有到期批次时连续执行，不在批次之间固定休眠；队列空闲时每分钟检查，提醒维护和主源调度也保持每分钟频率。详情成功后 24 小时复查，索引或单项详情失败 5 分钟后再检查，保留旧资料但不续其检查时间，失败条目不阻塞其他到期条目。索引成功不等于生日详情已检查，列表数量异常下降也不覆盖有效索引。页面与提醒只读本地名册，不请求外站。

SchaleDB 原始名册、外部最小资料和合并名册独立保存；短事务原子发表合并结果，源故障不会让另一个来源假装失效或获得新的检查时间。网络同步和提醒维护独立处理错误。生日任务进程中断后，租约到期时持久登记 5 分钟恢复等待，再继续未完成任务；不会因此跳过失败冷却。

资料快照按内容去重。每天最多清理 20 份超过 90 天且未被当前资料或提醒审计引用的旧快照；仍被提醒引用的资料不删除。

## 群提醒

群提醒还需启用现有通知配置，并在通知管理中订阅目标群的生日提醒。默认 09:00、生日当天，可另外选择提前 1 天或 7 天；群总开关仍有效。生日订阅和模板独立于作品订阅，修改生日设置不会改变作品消息的订阅代数或取消作品消息。

首次开启只接收开启之后到期的提醒，不自动补发历史日期。重启时仅恢复当前发送日内到期且尚未登记的摘要；每个发送日期与提前天数组合只登记一次，多个同日生日合并成一条消息。按每个人物生日的实际来源检查 48 小时有效期，过期人物不进入新摘要，不影响另一来源仍有效的人物。Kivo 详情还须与名册的事实哈希和已确认身份匹配。当天恢复有效资料可补齐尚未登记的摘要；一旦摘要已冻结，新增人物、恢复或实装关联均不追加重发。跨日不继续自动发送昨天的摘要。

消息在登记时冻结目标日期、完整姓名、群目标和提示语，沿用通知 Event → Delivery → Jobs → OneBot 投递链。模板修改不改写已登记消息。投递前复查生日全局、提前天数、群订阅和群总开关；关闭后重开不会复活旧代消息。结果未知的消息保持未知，不盲目重发；管理员确认后可使用现有历史补发操作，仍校验权限和当前订阅。

生日页的“手动同步”只登记资料任务，预览仅使用合成示例，不向真实群发送。普通测试使用合成 JSON、数据库 fixture 和替代 transport，不访问真实来源或群。
