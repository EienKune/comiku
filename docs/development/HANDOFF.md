# Development handoff

This tracked document records reusable implementation constraints. Business rules live in [architecture](../architecture.md), configuration in [configuration](../configuration.md), and visual rules in [DESIGN](../../DESIGN.md). Keep machine addresses, credentials, real samples, local experiments and deployment session notes outside the public repository.

## Author creation

- Submit the base author fields and distinct-platform account identities in one database transaction. A failed account binding must roll back the author, tags and earlier account inserts. Keep provider/profile requests and image transfers outside the transaction; X identities require server-verifiable profile evidence.
- Creation retries use an actor-scoped UUID and a canonical hash of the saved business fields. Commit the request record and author together, serialize concurrent requests, reject changed payloads under the same key, and recheck current source/admin permissions inside the transaction. A committed replay must not depend on the original profile proof's expiry or provider timestamps.
- Keep the same request ID when a POST response is lost, and inspect the actor-scoped creation-result endpoint before assuming no author was saved. A missing result can race an in-flight transaction and never authorizes automatically replacing the key. The browser stores only this opaque request ID in session storage; drafts, proof tokens and files remain in memory. Reopening the same browser tab can recover a committed author, while unsaved text/files require re-entry. Closing the tab ends that browser recovery boundary.
- Creation action failures use a nonmodal top-layer toast: an ordinary body portal can be hidden behind the native author dialog or made inert by it. Do not steal focus or require confirmation. Expiry clears only the error, never the parent dialog, creation request ID, selected files or upload recovery state. Pause expiry while hovered, clean up timers on replacement/unmount, and allow identical failures to appear again on an explicit retry.

## Author management notes

- Account binding/restoration must lock and recheck the active parent author before account writes, in the same author-to-account order as archive. A prior read outside that lock can create an active account after the author was archived. Author deletion in the UI is the existing archive operation: pin nickname/revision when confirming, require the exact nickname, retain works/history, and leave restoration to the existing administrative backend.

- Author forms keep tags as choices, not comma-delimited text. Existing choices submit immutable tag IDs with their observed revisions; explicit new names are separate. Resolve references before any author/tag-link write and reject stale or removed references rather than recreating their names. All catalog/link writers, including the whole CSV batch, take the same short transaction-scoped catalog mutex before tag/author rows; ordinary reads do not. Batch new-name insertion and lookup instead of per-tag round trips. No provider or file network request belongs inside this lock.
- Keep the original creation hash algorithm for committed legacy name-format replays only. New intent hashes use sorted reference IDs/revisions and normalized new names, without consulting current tag names; replay committed results before revalidating the catalog. Old-format uncommitted writes require a page refresh. CSV preview pins references and commit validates them; strip preview-only errors before nested request validation. Enforce both display-name and normalized-name column limits, since Unicode lowercasing can expand a name.

- Author/account notes are nullable plain text with a 2000-character request limit. Preserve omitted PATCH fields and normalize explicit blank/null to SQL null; source profile refreshes must not erase an omitted note. Notes share the existing author/account revision fences and do not create an additional history store.
- Keep notes in `ManagedAuthorDto`/`ExternalAccountDto` only. Public author, list, candidate and account-summary serializers must remain explicit allowlists. The management form reads `/authors/:id/managed` under `authors:manage` and uses its own query cache; never populate a public-author cache with a managed response.
- Historical author-creation hashes excluded notes. Add hash keys only for nonempty normalized notes at both author/account levels, so old committed requests replay unchanged. Blank/null/omitted notes must hash identically; changing a nonempty note under the same request key conflicts.
- Dirty notes follow the metadata form baseline and survive background refresh and failed attachment retries. A failed public or managed background read must retain the cached editor and upload state, with a nonfatal retry status; an error-only page wrapper would unmount the form and discard both. A clean newer managed snapshot may hydrate notes; only explicit load-latest discards dirty fields. The synthetic notes integration test requires the usual disposable `_test` database and exercises HTTP role/privacy, revision, persistence and old-request compatibility; unit/UI checks alone do not certify a migrated database or browser layout.

## Candidate review editing

- Image adoption and source ordering are different facts. Import the ordered subset atomically with the selected candidate revision; never save the candidate media order first. Retain all source media/file references, and map each WorkImage to its exact CandidateMedia ID rather than only its file ID (a source can reuse a file on different pages).
- New import replay compares the original pre-import revision and ordered provenance IDs before returning the existing work. Current WorkImage identity/order has no mutation path; adding such a path requires an immutable import receipt before changing this comparison. Preserve legacy omitted-request replay; do not invent a revision or an adopted=false result for unknown legacy provenance. Backfill only an exact source-post/order/file match.
- Source inspection is lazy and follows works:read, including unselected source media. URL signing must recheck work-to-source-post-to-media binding, not accept an arbitrary candidate media ID. Return only safe source DTO fields; candidate metadata may later be enriched, so distinguish its current text from Work.sourceText's imported snapshot.

- Candidate import locks the observed author with `FOR SHARE` before locking the candidate with `FOR UPDATE`, then re-reads both the binding and business state. Require current authorization and an active author before creating a Work; a concurrent reassignment conflicts rather than checking the old author. Preserve imported-request replay and per-item batch outcomes. PostgreSQL regressions cover mutations after the initial read and author updates blocked by a valid in-flight import.

- Author suggestions debounce their own paginated reads; only explicit single-author confirmation changes the review scope. Keep draft input separate from the selected author ID and consume cancellation signals so late searches cannot replace current suggestions.
- Keep per-post ordered image-subset drafts and their original revisions at page scope, independently of membership snapshots and panel mounts. Applying an adjustment is local; only final import writes the subset. Ordinary model refreshes do not discard drafts; real media/version changes require explicit reset. Reset must remount local editor state even when the freshly read revision equals the already open editor's revision. Batch completion only settles the same selection generation and draft version. An uncertain response freezes the exact manifest for replay, including after closing and reopening confirmation. Warn on route departure or hard refresh, without promising browser-close restoration.
- ImageLightbox can portal into an active native dialog, with top-preview Tab/focus/Escape ownership and connected focus restoration. Suspend its keyboard/focus trap when another native modal is above it, such as the draft-leave confirmation; otherwise the hidden preview can capture that dialog's keyboard. Share one visibility observer for image thumbnails and sign originals only for the current preview. Work source reads and bulk-confirmation image expansion remain lazy.

## Author attachments

- Evidence reads distinguish loading, failed reads and confirmed empty results; keep cached evidence visible on a failed refresh. Removal confirms a pinned author revision and does not change authorization status.
- Manual candidate upload keeps per-group checkpoints after each order/metadata response and each successful batch import. Retry only unfinished steps at their returned revisions, including when another group fails; imported groups cannot block retries if their author selection later becomes unavailable. Require explicit initial author selection, and retain ZIP/GIF support and source-specific limits when reusing the file picker.

- Direct-upload admission lasts 24 hours, independently of accepted jobs and terminal receipts. A matching queued/reclaimable or live leased job protects its staging after that deadline. All adoption transactions lock and validate their job lease before actor/resource rows, then complete the session atomically. Reconciliation and cleanup must never regress a terminal state. Finalization samples its deadline after the session lock.
- Keep terminal receipts for seven days from first terminal time. Delete staging in two phases: after a 15-minute write-grant grace, then before receipt removal; failed passes retry idempotently without dropping keys. A successful cleanup pass does not prove an already in-flight external PUT cannot finish later. Terminal DTOs expose no manifest; the retained manifest contains only keys after cleanup. Exclude direct-upload staging from bucket age-based lifecycle rules before upgrading.
- A missing attachment receipt is an unknown outcome, not permission to automatically upload again. Keep 403/network recovery locked. Only an explicit resource/attachment refresh may exit confirmed-404 recovery; retain successful author/metadata checkpoints and refresh the public avatar state separately from managed data.

- Selecting images is local form state. Once an author creation response has succeeded, preserve its ID and completed binding steps when a later attachment fails; do not restart author creation for an upload retry. Attachment recovery is separate from the actor-scoped creation-request recovery described above.
- Keep a known direct-upload session until its server state is inspected. A lost finalize response can leave a locally pending session completed remotely; local expiry must not unlock file replacement. Recreate only a confirmed failed/expired session or a server-confirmed pending session past expiry. Attachment adoption and session completion share a transaction, so completed sessions must not be uploaded again.
- Author metadata and authorization attachments share the author's revision. Preserve upload recovery across query refreshes; synchronize a clean form with newer data, but keep dirty edits on their original baseline until the user explicitly loads the latest metadata. A successful metadata save followed by an attachment failure must not PATCH the same metadata again on retry.
- Detail avatar selection belongs to the existing editor's file/upload session, including its locked and result-unknown states. Keep the avatar trigger and preview in that state owner, preserve dirty metadata on cancel, and retain a read-only summary when managed details initially fail. Input actions align with the control row rather than the combined label/control/hint height; nested platform tabs must not inherit page-level margins.
- Managed author details render the editor without a duplicate summary or edit heading; keep summary rendering for read-only access and initial managed-read failure only. Creation and editing share the avatar picker's companion field layout: the avatar column stays fixed and selection/cancel status occupies a full following row, so selecting a file must not shrink or shift the nickname on narrow screens. Disable the avatar's own native controls rather than the containing fieldset, since an upload lock must not inadvertently disable the companion metadata input. Shared Avatar uses grapheme initials and read-failure fallback; a failed local preview preserves the selected file/upload intent and cancellation restores the platform avatar.

## Author collection controls

- The author account page has one business collection switch (`fetchEnabled`); technical adapter controls require `system:manage` and are not author-page actions. When consolidating legacy disabled gallery states, preserve the pause as `fetchEnabled=false` before normalizing the internal state permission. Increment the affected revisions but do not clear cursors, checkpoints, cooldowns, errors or leases; otherwise the single switch may either restart an intentionally paused account or fail to enable it later.
- Compare canonical X handles before requiring profile proof: `name`, `@name` and its homepage URL describe the same identity. Ordinary pauses and notes must not submit an unrelated expired profile proof. New binding, real handle changes and reactivation retain trusted identity checks. Source composition validates one available adapter per platform at startup; the registry can retain inactive implementations and isolated legacy adapter tests without enabling runtime fallback.

- New X/Pixiv account forms share capability-backed collection controls: default to enabled and 24 hours only when a configured available source supports it, otherwise select a supported fallback or save information only as false/none. Wait for the first capability read before submitting new accounts. Existing account flags/windows are the baseline, including paused accounts whose saved range is no longer available; capability failures must not prevent ordinary metadata maintenance or pausing.
- Derive defaults only for untouched new accounts. An explicit choice or submitted creation intent must survive later capability responses, retries and response-loss recovery under the same creation key. Capability changes may block an unsupported activation but must never silently replace the submitted window or enable a previously disabled account. Keep the query shared and metadata-only; rendering these controls must not resolve profiles or start collection jobs.
- When collection is off, retain an explicit `none` choice even after all capabilities disappear or fail. Otherwise an unsent draft holding 24 hours/seven days becomes impossible to save as information only. Keep the unavailable window until the user explicitly chooses `none`; never normalize an existing paused window or a submitted creation payload automatically.
- Collection checkbox labels need a dialog-scoped inline layout: the file-field group's generic label grid otherwise places the checkbox and text on separate rows. Do not change global form-label rules to repair one feature control.

## Author pagination

- Directory X/Pixiv state filters are independent AND predicates over active accounts. Disabled requires an existing account with its switch off; unlinked means no active account and ignores soft-deleted rows. Page/count share the same SQL predicates and the cursor digest binds both filters. Summaries select only the additional `fetchEnabled` boolean, never managed notes, adapter state or upstream metadata. A true switch is separate from current authorization and does not certify runnable collection.
- Directory search is debounced and cancellable; a new filter key starts a new page chain, while changing card/list view preserves it. Do not load an old page while a new search is waiting. Keep PlatformLinks' original icon mode unchanged for other callers; account mode places identity beside the icon, keeps paused homepages usable and reserves separate authorization space for long names.
- Compact filter rows need a minimum inline size even when flex-wrapping: zero-minimum equal flex fields can hide the difference between selected values after the clear button appears. Let narrow screens wrap filters, and anchor the first dropdown toward the viewport interior.
- Author lists filter and rank in PostgreSQL, select at most `limit + 1` positions, then hydrate only the visible authors and account summaries. Do not restore a full `findMany`, JavaScript sorting/slicing, or adapter checkpoint/metadata hydration for ordinary lists. Exact totals still require a filtered `COUNT`; contains searches may scan matching author/account indexes and are not constant-cost operations.
- Page order is X-handle exact/prefix/contains priority, followed by display name under PostgreSQL `C` collation and UUID. The cursor carries that tuple and a versioned normalized-filter digest; reject old/mismatched/malformed cursors. A deleted anchor can still continue by tuple. A short repeatable-read transaction keeps each page's positions, total and summaries consistent; separate pages remain live and do not freeze author membership or edits.
- Manual-upload author choices use server-side `authorized` filtering, debounced search and continued pages. Keep the selected author independent of the search results; recheck its current authorization on refresh/poll and clear an ineligible choice. Upload and metadata mutation endpoints remain the final authorization boundary. Tests use synthetic authors/accounts and never certify real-source capacity or browser layout by themselves.

## Source ingestion

- Candidate card layout is scoped to `candidate-card.css`; do not adjust shared work/author card title or footer selectors to fix it. Reserve three collapsed body lines and one expansion-control row even for empty text, keep the status unbroken, and use fixed selection/order/origin slots. Model category and failed-image retry can coexist on partially successful multi-image posts; retry preserves successful analysis.
- Candidate selection stores the first observed revision and is capped at the batch API's 100 items. Select/cancel-loaded applies only to loaded IDs, including discarded lists; imported items cannot be selected for restore. Discard confirmation captures the exact selection/revisions, and late results must not clear a newer selection of the same ID. Partial failures stay selected. Tag truncation must reserve its overflow control within two rows while keeping all original hashtags and both rule directions in the accessible overview; do not duplicate interactive model nodes for measurement.

- Candidate author portraits must use the shared bounded Avatar, not a bare image under the legacy `workspace-author-avatar` class. That legacy class has no size constraint; successful profile synchronization can otherwise expand a portrait to its intrinsic dimensions and push author details outside the card. Exercise candidate cards with an available avatar and its read-failure fallback, not only the initials-only case.
- X identity evidence comes from gallery-dl's native info metadata, not timeline scanning or a client-supplied timestamp. A new binding, changed handle or collection reactivation requires a short-lived server-signed proof bound to the actor, author scope, numeric ID, handle and avatar snapshot. Refresh a bound account by its immutable numeric ID to discover a renamed handle; an explicit replacement handle must resolve to that same ID. Existing account metadata maintenance and pause remain available without platform requests. CSV preview and submission both resolve and compare any supplied numeric identity before enabling collection.
- A same-ID proof refresh with a null avatar after optional download failure preserves the server-observed avatar. Explicit null without a proof still removes the avatar; identity trust and revision fences remain unchanged.
- Profile avatars and post media can use different CDN hosts, including platform default-avatar hosts. Keep the avatar allowlist separate from the post-media policy; adapters without a dedicated avatar policy retain their existing media-host fallback. Optional avatar diagnostics must identify missing/download/store/sign stages using controlled reason, error-name/errno and numeric HTTP/size evidence only, without URLs or arbitrary upstream text. A preview-signing failure retains an already stored file ID and its proof binding; identity resolution and revision fences still apply.
- Pixiv profile synchronization is optional for manual ID-only maintenance, but synchronized profile/avatar evidence requires a platform-bound proof matching the current numeric ID. Clear the pending proof when a new ID changes, reject late or mismatched results before updating any profile fields, and keep a bound account's ID read-only. Creating an author keeps both platform drafts and allows no account. Explicit sync adopts the name and an available avatar; tab switches alone do not. Keep the chosen avatar source independent of the active tab; a null-avatar result retains only still-fresh same-ID/same-handle avatar evidence and its matching proof, or the manual/other-platform avatar. A changed canonical X handle must use the new response and proof even when the stable ID matches; apply this retention rule to both creation and account binding. Later manual edits/uploads override the adopted values. Do not reset notes, collection settings or creation/upload recovery.
- The pinned gallery-dl `PixivUserExtractor` inherits a no-op `Dispatch.initialize`; call `common.Extractor.initialize` explicitly before `PixivAppAPI.user_detail` to initialize its session without entering `items` or artwork dispatch. Native `user_detail` also caches by ID in `common.CACHE_MEMORY`; isolate and restore that cache between synthetic fixtures and subcases instead of bypassing the native method.
- Interactive profile metadata shares the platform's durable network scope, credential generation and authentication/cooldown gate, but has its own single execution slot alongside the platform's one collection/recovery job. Admission ignores live collection/account leases only after platform state exists; initial state bootstrap still requires a drain. Worker capacity excludes profiles only in network/source scopes; credential activation/recheck still drains both kinds. Reserve/release leases in short transactions and keep native requests outside them. Merge outcomes under the platform row lock: success cannot clear an authentication pause or active cooldown; authentication takes precedence while cooldown deadlines independently retain their maximum, including rate/auth races. Never acquire scope/job locks inside outcome merging. The native profile process has a 45-second timeout under the shared 60-second job lease; optional avatar download failures do not invalidate verified identity. Expired interactive leases and previously requeued interactive rows terminate as failed during scoped job recovery; they never replay an HTTP-owned profile request. Synthetic native-profile, proof-tampering, actor/author/TTL, maintenance and scope-failure tests complement deployment-only real-session verification.

- A stable platform user ID is immutable on account edits. Reject a changed ID before any account, adapter or history writes; compatibility inputs with the same ID still allow nickname/handle edits and pause. Unbinding/restoring is a separate lifecycle operation and must keep the original source identity. Profile synchronization must not overwrite an edited account's read-only ID when a result belongs to another account.
- A configured collection adapter does not imply profile-resolution support. Check `resolveProfileByHandle` before consuming a metered budget, and distinguish an available adapter lacking that capability from no available X source. Gallery collection alone does not establish trustworthy profile identity; complete profile validation and handle matching remain a separate boundary.

- Candidate model badges prefer policy priority (positive, unmapped/uncertain, low) across valid current images; use score and taxonomy order only within the same tier. Keep this consistent in the SQL projection and summary-based presentation. Post sorting still uses the maximum ranking score independently, and frozen review reasons/group membership must not move as a side effect of a badge fix.

- A deterministic download policy rejection is not a transport failure. Preserve controlled size/type/empty/URL reasons and byte limits at the downloader boundary, persist the exact media reason and stop automatic compensation for size/URL policy rejections. Empty-body/type errors remain retryable because upstream HTTP-200 error responses can be transient. Keep valid sibling media and unrelated posts. Check both declared and streamed bytes and cancel rejected bodies. Configuration changes do not automatically reopen terminal gaps; use explicitly authorized recovery while retaining previous campaign history. Source download limits are independent of manual-upload and decoded-pixel limits.

- Post/ordinal media IDs are stable slots, not immutable assets. Before reusing a stored slot, including a historical candidate created before discovery ledgers, compare its proven source origin/path with the verified manifest. Signed query-only refresh may reuse it; missing identity or changed asset paths require an explicit unresolved ledger outcome and must not certify an old file as a new asset. Preserve terminal attention/excluded reasons and human candidate/Work state through adoption and campaign reconciliation.
- Execution-time gate deferral must refund the attempt and the lease's own durable fairness advance in one transaction. Lock the scope before the job; require a live matching job lease and the same queue receipt token before restoring its prior budget. An absent prior row differs from an existing zero budget. An expired/replaced executor must never restore an old budget over a later claim.
- Partial media failures need a sanitized diagnostic event at the absorption boundary, and post recovery needs its own job/attempt/campaign context. Keep structured media/storage/native scope and reason, do not duplicate already emitted per-media failures in the recovery summary, and do not label gate waits as business failures.
- A generic native HTTP hook cannot certify a metadata 404: only the exact active Pixiv `/illust/<id>` AJAX GET may establish that evidence. CDN HEAD 404s belong to native media fallback and cannot authorize a complete metadata-pending stub.


- Discovery coverage and completed candidate media are separate. Register each verified manifest or explicitly proven catalog/timeline metadata gap before committing a provider cursor. Failed IDs alone never prove enumeration: the native envelope must partition bounded verified IDs into resolved IDs and typed metadata failures. Unknown identity, malformed metadata, authentication and incomplete pages keep the window unfinished.
- A discovery ledger formally references each successfully stored media file. Candidate creation requires verified nonempty metadata and every manifest slot; refresh only missing media URLs, and reject changed manifest identities. File cleanup locks and checks all references before marking deletion, and ledger attachment checks the same file lifecycle under lock. A crash before file attachment may leave an unreferenced upload; it never advances discovery without a registered gap.
- Covered scans with remaining gaps finish their account target and batch as partial failure. Original scan history remains unchanged after independent recovery. Recovery uses the existing platform network scope and recovery queue, with one bounded due selection per account, eight business campaigns, and three background-job attempts per campaign. Gate waits and process restarts do not allocate another campaign. Exhaustion reconciliation compares the exact recorded scan epoch/owner before releasing source leases.
- Recovery is an internal single-post capability, not a user-facing fetch entry. Successful offline finalization cannot certify platform credentials. Administrator operators can inspect at most 100 safe unresolved terminal gaps with `node dist/ops/source-discovery.js needs-attention`; this read-only command loads no AppModule or optional model/native runtime and emits no source URLs or raw diagnostics.


- Native Pixiv `caption` can contain HTML. Its AJAX sanitizer unescapes entities before emitting metadata, so parsing that result again can erase encoded literal angle-bracket text. Preserve the existing AJAX caption until the bridge parses HTML once, keep optional caption/comment enrichment disabled, and copy every new helper into the built adapter assets. Natural duplicate metadata refreshes must retain nonempty source descriptions without changing Work fields or human review revision, or redownloading media. Seven-day first sync is exactly 604,800,000 milliseconds and must not replace successful account coverage.

- Decoding an entirely encoded URL or JSON value can create a newline/quote before its private suffix is removed. Omit an ambiguous field before those delimiters are introduced, including on malformed percent-decoding errors; even an error placeholder can introduce a new delimiter. Handle sensitive keys before credential-fragment replacement can erase a key. For prior controlled diagnostics, clean allowlisted scalar fields before bounded JSON serialization; re-decoding the serialized object can erase useful safe context. Reset post-validation stage and media correlation at every post boundary; a later invalid post must not inherit an earlier media ID. Use independent synthetic credential and opaque-header canaries when asserting that nonsecret operational IDs survive conservative fragment redaction.
- Prior-diagnostic JSON must tolerate lone Unicode surrogates in upstream text. ASCII-escape that serialized context and measure the exact returned representation; strict UTF-8 byte counting of an unescaped surrogate can throw while constructing the original controlled failure.

- Preserve native failure reason and scope separately from the safe public error code: source access denial is not proof of shared credential expiry, and CDN errors stay media-scoped. Extract private diagnostics explicitly; keep them non-enumerable and out of persisted/API errors. Sanitize full URLs before credential-fragment replacement (replacement can introduce spaces), redact decoded/escaped secrets and sensitive JSON lines before head/tail limits, and omit excessive input rather than truncate it before redaction. Fixed field/header and reason allowlists prevent arbitrary upstream objects from bypassing the log boundary.

- Coverage time is distinct from the newest observed publication. Fix each scan's lower/upper bounds before network work, advance successful empty scans, and retain the same bounds on failure/resume. Backfill coverage conservatively from a successful item's start, never from its latest post. Do not apply a legacy `since_id` in a way that truncates an intentional time overlap.
- Pixiv v3 cursors bind both bounds and the successful catalog baseline. Only final, fenced completion replaces the separately stored baseline. Initial metadata bootstrap is a one-time cost; later scans use ID differences plus a bounded prefix. Keep known future IDs outside the baseline, including minute-truncation ambiguity in an empty initial window. Do not turn a per-job page budget into a cumulative cursor ceiling that can never resume. Omit large discovery caches from account, author and run queries.

- Account-wide discovery coverage and fixed unfinished windows belong to `SourceAccountScanState`; provider cursors and discovery baselines remain adapter-owned. Do not derive shared coverage by taking the latest timestamp across providers. Migrations inherit only gallery coverage backed by a matching successful item, and retain its unfinished window separately. Switching an adapter rebuilds its protocol state from shared bounds; a changed stable identity gets a new account.
- Fence every protected write and stale failure with the captured account scan epoch, management revisions, source leases and background-job lease. Cleanup must check the shared epoch before clearing an adapter lease, including retries of the same job/run. Lock order is job, actor, author, account, shared scan state, adapter, candidate, file reference; requests/downloads remain outside these transactions.
- Daily composition registers configured gallery-dl clients only. Keep the generic registry extensible and retain retired implementations, synthetic tests and technical history. Old credential inputs must not register retired clients or expose their toggles in daily account DTOs. Author lifecycle tests that activate collection must declare an explicit synthetic capability instead of relying on implicit unavailable runtime clients; their network methods should throw if called. Keep genuinely unconfigured profile-only and rejected-activation cases separate.
- Interrupted collection must resume the existing run/account/adapter record. Recreating it violates its unique constraint; preserve counters, skip completed accounts and propagate cancellation instead of treating it as an ordinary platform failure.
- Exhausted background jobs may never re-enter their handler. Recovery must settle the run/items and release stale account locks without advancing an unsafe watermark.
- gallery-dl may omit unavailable media slots. Validate original-photo coverage and page completeness before committing progress. Skip unsupported Pixiv animations explicitly.
- Pinned gallery-dl uses `quoted_id` for a post's referenced target and `quote_id` for an expanded quote context; keep a user's own attached images while excluding the expanded target's images. Pixiv sanity entries must pass native AJAX resolution before checking their real author, date and type; unknown metadata must not masquerade as complete static media.
- Bounding Pixiv App API pages does not automatically bound the native sanity iterator. Keep the App and bounded AJAX supplement stages separate: retain native single-work conversion, validate real metadata, bind versioned cursors to source/window, check catalog fingerprints around each AJAX page and recheck the App head before final completion. Lower IDs or an old metadata page do not prove a safe time boundary. Reject missing metadata and excessive image counts before native allocation; optional comments/user enrichment must not bypass the request budget. Disabled sanity does not establish AJAX-only coverage.
- Persist service-observed publication-time/ID pairs alongside the page cursor so interruption and the 100-page guard do not lose the maximum already seen. Bind the checkpoint to source, adapter and cutoff, strip any adapter-supplied replacement, and apply it to formal watermarks only after complete coverage. X/legacy cursor restart behavior is separate from resumable versioned Pixiv cursors.
- Pixiv list/detail publication timestamps can differ by minute truncation. Accept exact equality or one endpoint's UTC time truncated to the other's minute; two differing nonzero-second times are still drift. Use a conservative UTC-minute bound when selecting App/AJAX candidates near cutoff, preserve the native detail time and let the service apply the exact boundary. Real schema/precision checks complement synthetic fixtures.
- Adding a source client requires backend capabilities and author-form wiring as well as registry registration. Pixiv starts with collection disabled; the X form may enable collection when a supported capability is available. Editing must preserve existing collection settings.
- Removing a configured adapter must not prevent maintaining or pausing an existing account/channel. Preserve the previous sync window when pausing; require available capabilities for new activation or a changed window. A token authentication failure is separate from a missing runtime configuration. Keep pause controls accessible when capability discovery fails.
- Technical collection history, including an individual run's details, belongs to System Management and requires `system:manage`. Manual source synchronization remains a source-role business action; return only the run ID and business status from its POST, including when reusing another actor's or a scheduled batch, so it cannot bypass history permissions. Its empty account selection targets all eligible authorized accounts, independently of candidate-list filters.
- Manual and scheduled enqueue paths share the same transaction lock. Reuse an equivalent active account set and reject overlapping different sets; do not rely on a per-page disabled button. Test actual execution after exhausted-job cleanup, not only the allocation of a new run ID.
- Discover progress through the read-only, shared business summary, not a page-local run ID or the full technical history. Aggregate only the selected active/latest-manual run IDs; never load upstream payloads or repair jobs in a GET. A running job without a lease cannot be reclaimed by the worker and must not produce an endless spinner. Keep real POST conflicts visible even when a following status read discovers another active batch.
- The candidate sync control polls only in the foreground and restores state on mount/focus. Status inspection uses hover or keyboard focus on the existing control, without a separate expansion button or click-pinned popover; a disabled button needs a focusable wrapper. Inspection never creates a task. Cancel a status request started before POST before fetching canonical progress; it must not overwrite the newly committed run. Handle immediate completion as well as a polled running-to-terminal transition, and clean up timers when leaving the page.
- Fence protected writes with the background-job row and lock author/account/adapter rows in the management-compatible order. Network requests never belong in these transactions. Recheck actor permissions for existing observations as well as new candidates; stale failures must not clear another execution's lease or overwrite a management change.
- Lease fencing holds only when the same transaction client is passed through the protected write; an autocommit `this.db` check is only an instantaneous check. Parent user/author/account rows use share locks so management updates are fenced while foreign-key key-share checks remain compatible; adapter state uses a no-key-update lock. Recheck a terminal job after locking it before clearing its source leases, and leave a live final attempt alone.
- One Pixiv work can outlast the 30-minute source lease while its background job remains healthy. During a long page, renew the source lease at most once every five minutes under the same job, actor, management-row and revision fences; keep downloads and storage outside that transaction. A lease already expired or replaced must still fail instead of being revived. The synthetic 1,000-image case completes with six additional renewals rather than one extra transaction per image; this is a liveness regression check, not a live-platform throughput measurement.
- Recovery must clear current error fields on running/success transitions and retain a separate recovery event. Stream actual download bytes and cancel at the limit; Content-Length and a timeout alone do not bound memory or transfer.

## Image analysis

- Use `ImageAnalysisAdapter` for model integrations. Forward migration `20261031000200_remove_legacy_candidate_classification` removes retired manga/photo decisions, suggestions, enums and cached tag disposition; the legacy hook, write endpoint and routing reads are already retired. Use the normal database backup procedure before upgrading. Deploy the API and worker with this migration as one coordinated upgrade: old Prisma runtimes still selecting the removed fields must not keep running against the cleaned schema. Do not remap legacy records to model labels or delete modern model results, `classScores`, category tags, media type `photo` or human candidate/Work review state.

- Per-image classification scores use an authorized lazy read, with one ordered taxonomy and aligned numeric vectors. Restrict the SQL join to the configured model and active file checksum; project bounded scalar/vector fields in PostgreSQL instead of hydrating stored evidence. Revalidate the complete taxonomy and predicted winner with empty projected evidence. Missing, malformed, failed and pending rows carry explicit states, never invented zero scores; keep every media row in current visible order.
- Score inspection mounts its query only while the portal is open. Always refresh on reopening and hide cached vectors until that opening has a fresh successful read; errors hide scores so a model switch cannot display old scores as current. Track success per opening with the query observer, not just a cached timestamp. Keep the mounted table during later background reads in that same opening so polling does not reset its scroll position. Only pending visible rows may poll. Portal crossing and internal scroll must preserve inspection, while Escape/outside/unmount clean up listeners and requests. Position the portal after the parent ref has mounted as well as after data changes: a child's first layout effect can run before the portal ref is attached and otherwise leave a slow loading state invisible.

- Candidate review membership belongs to a short-lived database session, shared across all three groups. Background invalidation rehydrates cards without replacing the session; only explicit list refresh, expiry or model/filter mismatch establishes new membership. Keep fetched-time bounds fixed for the scope. Preserve first-selected revisions across pages and replacement, and remove only successful/unchanged bulk outcomes. Session/entry deletion is bounded; do not add cascading session cleanup or hydrate the entire candidate filter in Node. See [review-session contract](../candidate-review-sessions.md).
- Give compound indexes on long table/column names an explicit short Prisma `map` and matching migration identifier. PostgreSQL truncates identifiers at 63 bytes while Prisma may choose a different shortened name; successful migration execution alone can still leave schema drift.
- Session expiry is a concurrency fence, not just a timestamp comparison against request-start time. Choose the lock mode before admission: due renewals acquire `FOR UPDATE` before reading fresh database time/state; ordinary readers use compatible `FOR SHARE`. A statement-time timestamp can become stale while UPDATE waits for another reader, even inside a materialized CTE. Recheck whether renewal is still due after acquiring the write lock, and reject a zero-row CAS under that lock. Never upgrade shared readers to write locks; if the threshold crosses during a shared read, the next request can renew. Replacement/LRU updates and bounded cleanup's `FOR UPDATE SKIP LOCKED` stay exclusive. Otherwise a delayed read can revive an evicted session or reopen a partially cleaned snapshot. These locks cover snapshot metadata, not candidate business rows.

- Pausing a queue must exclude it before fairness selection. A claim gate that only defers historical jobs can repeatedly select that paused queue when the primary budget is spent, starving new work. Analysis registers one indexed activation read per claim through queue availability, retaining the gate as final defense.
- Analysis uses its own global lease slot and persistent 3:1 incremental/historical policy. Persist activation cutoff and immutable media/key intent in the same registration transaction; never derive purpose from restart time or include queue policy in model identity. Bootstrap only an absent drained activation; all later model/disabled changes require generation CAS. A stale worker must roll back its claim, not rewrite global activation.
- Upgrade queued legacy analysis in bounded chunks under analysis then heavy scope barriers; never move running work. Scope barriers precede stable job locks, then candidate locks. Claim gates must not acquire analysis scope while holding a heavy claim barrier. Protected handler writes assert the lease before candidate locking. Drain and stop old workers before upgrading or switching models; lease expiry alone cannot stop accepted remote/native inference.
- The compiled analysis maintenance CLI has no AppModule/adapter runtime dependency. Test its shipped dependency closure without source/TSX/model assets. Isolated PG fixtures own and restore their activation generation and queue budget, and clean only their own media/jobs. Synthetic concurrency/resource markers are not real-model or production throughput claims.

- Successful per-image evidence is independent from sibling completion. Do not gate ranking, categories or promotion on the aggregate state, and keep failure retry separate from score. Version bounded summary repairs and mark malformed/empty results processed too. An unavailable model cannot certify a repair: leave its version unprocessed so same-key re-enable rebuilds successful history; selecting all successes with a missing score can permanently consume the first 20 recovery slots. Poll eligible media work, so failed plus queued remains pending while terminal-only media stop.

- Candidate refresh cannot rely on queued rows in the loaded page: newly created rows may not be scheduled yet, and pending rows can be outside that page or group. Return an optional scope-level `analysisPending` hint and retain the old-response fallback. Count only active, undeleted media for undeleted authors that still need current-model analysis or summary provenance repair; a successful active image must not keep polling forever for an unavailable sibling. Disabled models and terminal failures stop polling. Use the existing list query's filtered relation count, not a new queue-scanning endpoint.

- Adapters declare their ordered taxonomy; generic validation supports binary and multiclass outputs. Taxonomy is part of the immutable model identity. Review priority is independent of the class probabilities.
- A model identity change creates new results; never rewrite historical successes to impersonate the new model. Persist original SHA and identity, retain bounded retries and verify the lease under the candidate lock before aggregation.
- Candidate summaries carry `analysisModelKey` provenance. Only valid evidence matching the configured active adapter affects priority/sorting; mismatches and disabled adapters preserve history but do not display stale priority. The worker can rebuild at most 20 unmatched summaries per scan from actual current-model results without repeating successful inference. Configure API and worker consistently and restart them together on model changes.
- Analysis does not change human review status or revision. Disabled/unavailable models must not fabricate a classification.
- Candidate cards add actual classifier category tags, with names and semantic colors supplied by optional adapter presentation metadata. Keep original hashtag disposition independent; do not add model-hit, inference-state or score-band badges. Render only validated current-model categories, without applying the review-routing threshold to their display. Presentation changes do not change model identity or trigger inference.
- A post's single category tag prefers the highest review-policy tier across valid images, then ranking score and taxonomy order within that tier; winning-class confidence does not replace the sorting score. Cache ranking separately and rebuild legacy scoreless summaries from persisted results. Promotion still checks every image; BA-winning images promote without an extra confidence cutoff. Never rewrite model outputs to repair review grouping.
- Adapter routing uses any valid current-file winning positive class without an extra confidence threshold. The unused confidence-policy field has been removed. Optional lowPriorityLabels defaults to empty. Only all-image valid current-model/current-SHA low winners establish model-negative evidence. Freeze original hashtags, both tag directions and routing reasons with the session; do not join live rule names onto a frozen group. Capture aliases/group metadata in one MVCC query and pass that immutable rule snapshot to ranking. Old four-group sessions require refresh. Rule saves must not UPDATE every candidate, invoke inference or download media.
- Regression tests for removed legacy storage must recreate predecessor records in an isolated synthetic schema and execute the forward cleanup there, comparing modern model evidence and human business snapshots before/after. Do not retain obsolete Prisma fields to keep fixtures compiling. Source commit concurrency tests pause at the protected candidate create operation rather than a removed tag-classification helper; preserve their real management-write contention checks.
- SQL vector validation must coalesce each item predicate to false before bool_and: PostgreSQL ignores NULL otherwise. Compare persisted scalar scores through numeric round-trip text rather than casting untrusted JSON numeric values to double precision; an in-range 1e-4000 can underflow and abort an entire list. Range-filter vector values before summing too: two individually representable 9e131071 numeric values overflow their sum even when the separate validity flag is false. Synthetic PostgreSQL fixtures cover missing vector fields, scalar drift, current-SHA checks, rule edits between snapshot read and materialization, frozen explanations, and legacy classification cleanup without changing modern model or human review data. These checks do not establish production throughput or real-model accuracy.
- Scope candidate IDs before aggregating tags and image results. Use set-based joins for source tables, materialize the bounded per-image validity projection once, and reserve LATERAL for each image's bounded vector. Correlated table scans can degrade after bulk ingestion with changing planner estimates; increasing the production query timeout is not a routing fix. Session-page live classification projections must use only that page's candidate IDs. The 50,000-post synthetic check uses one image and two tags per post; it does not establish capacity for arbitrary image counts or concurrent reviewers.
- Analysis refreshes may update cards within the same review session, but must not exchange section membership or ordering. Only explicit refresh, expiry or model/filter mismatch establishes a replacement snapshot. Coordinate active-card refreshes and a final read after queued work settles, pause background polling, and clean up timers/subscriptions without clearing cross-page selection.
- Keep the hashed BA extraction/pipeline/processor files byte-identical. Formatting these files changes their artifact identity. Preserve third-party license and attribution files when packaging runtime assets.
- Exact-byte runtime artifacts need path-level `-text` Git attributes as well as formatter exclusions. Check staged blob SHA-256, not only working-tree bytes: line-ending normalization can otherwise make a fresh Linux checkout fail the runtime integrity check.
- The BA runtime reads model paths from its process environment, explicit CLI flags or an optional JSON configuration; JSON-relative paths resolve against that configuration file. Model artifacts can remain outside the checkout, with no required repository directory. The runtime does not read executable code from a model directory or require training tools.
- Reuse a resident model with bounded handlers, one inference lock and a measured CPU thread budget. HTTP disconnect does not cancel an in-progress PyTorch call; shutdown must drain accepted work before removing hooks.

## Verification and operations

- Background jobs default to `global` execution scope and `default` queue. Claim/runNext callers may opt into another scope without adding a lease engine. Register the same queue policy in every worker; the `(lane, scope)` advisory lock and `JobQueueState` persist its consecutive-selection budget. Queue priority and ten-minute aging apply after queue selection. After taking the job row lock, re-read full job eligibility and payload: ordinary retirement/management writers do not hold the claim advisory lock. Reject a terminal, moved, delayed, exhausted or unhandled row before gate or fairness writes. Claim gates run under the job row lock in the short claim transaction and may pin database state; keep network/model/storage work outside. A returned `JobDeferred` delays an unclaimed job without consuming attempts or fairness; a handler-thrown `JobDeferred` restores only the current claim's attempt while the same live lease remains owned, including the third claim. Deferral reasons are runtime allowlisted and both waiting paths persist at least five seconds into the future to prevent refunded-attempt hot loops. Ordinary exceptions retain the three-attempt failure policy. Scope policies and claim gates are registration APIs; adding the analysis lane alone does not move existing handlers or start another worker loop.

- PostgreSQL JSON extraction must be grouped before JSON-key subtraction: `((value->'field') - 'key'::text)`. An outer pair of parentheses alone does not prevent operator precedence from subtracting unknown string literals. Wrap a new forward migration's DDL and backfill in one explicit transaction so a statement error cannot leave partial tables behind. Exercise the actual migration against synthetic PostgreSQL history before calling deployment complete.

- Use the pinned Node/pnpm versions. Run ordinary tests with synthetic fixtures; PostgreSQL integration tests require a separate disposable `_test` database.
- Serialize commands that regenerate ignored Prisma output in a shared worktree, including server tests, server type checks and API generation. Overlapping generators can remove or partially replace each other's output and cause misleading missing-type or `ENOTEMPTY` failures. Web-only checks do not need Prisma generation.
- Do not use a distant database connection to diagnose transaction timeouts as application defects without checking network latency. Do not reset a business database to fix test setup.
- Use the optional Python environments for adapter tests. A missing gallery-dl dependency in a different system Python does not establish an adapter defect.
- Capacity and live-platform coverage require explicit environment tests. A worker heartbeat, passing fixtures or a built image does not prove every collection job succeeded.
- Short object-storage signatures depend on correct host time. Inspect time offset and source reachability separately; a running time daemon does not establish synchronization.
- Probe API readiness on its own listener before checking a dependent reverse proxy. Stopping a systemd unit may stop services that require it; explicitly restore dependent test services, and retry readiness rather than treating `active` as proof that a listener is ready.
- Test connection admission without sending unread bytes when asserting an immediate overload response; TCP reset behavior differs across operating systems.
- Build scripts copy an explicit list of public non-TS runtime assets and required notices. They must not copy private configuration, model files or tests into production assets.

Before an authorized commit, inspect the full staged diff and untracked files. Commit messages describe the problem and concrete changes only. Keep verification records, deployment notes and remaining scope in the appropriate handoff or PR description; do not include environment secrets or unrelated work.

## Platform-scoped source collection

`source_account_fetch` jobs use the `network` lane, `source:x` / `source:pixiv` execution scopes and the `scan` queue. A run persists all account targets before any job starts, and is terminal only after every target settles. The single policy registration in `SourceFetchService.onModuleInit` reserves a 3:1 scan/recovery ratio; recovery handlers must reuse that policy instead of registering another one. Scheduler/reconciliation run in a separate short loop. A waiting account reserves only itself: a completed Pixiv target may be scheduled again while an X sibling waits.

Credential identity is a SHA-256 fingerprint of the controlled gallery configuration and its referenced cookie-file bytes. Reads are bounded to 1 MiB per file and 4 MiB total. Use separate per-platform configuration files and absolute literal cookie-file paths (no shell/environment expansion). Relative paths are rejected because gallery-dl can resolve them from the worker working directory, which differs from a config-directory interpretation. All referenced cookie files in that platform config participate in the fingerprint, including inactive sections; avoid placing unrelated platform sections there. Export browser cookies to controlled files; mutable browser-profile credential stores cannot be activated. The fingerprint is checked at claim and immediately before network work. A locally mismatched worker rolls its claim back without postponing the shared job, and backs off its own scope. Only an absent shared row may bootstrap, under the Jobs scope barrier and with old source/account leases drained. Existing workers and GETs never replace a generation.

To rotate credentials, first drain running platform/global collection and source leases, update the controlled local files, then run `pnpm --filter @comiku/server source:credentials activate <x|pixiv> <expected-generation>`. The expected generation comes from the administrator-only platform endpoint. Activation is compare-and-swap and leaves the new generation `unverified`; it is not a network verification. The administrator recheck endpoint releases an auth pause for the same local generation and wakes queued work, or schedules an eligible scan when none is pending. It does not shorten a trusted rate-limit cooldown. A real, fenced successful scan establishes `healthy`. Credential-derived pauses stay in platform state, so rotation does not inherit a stale per-account credential cooldown; source/media failures retain their own account state.

Before upgrading a worker from whole-run `source_fetch`, disable scheduling and drain all queued/running whole-run jobs using the old runtime. Then stop old workers and verify global job and account leases are drained before starting scoped workers. The new runtime refuses to execute legacy whole-run handlers; it does not silently convert, discard history or run them alongside scoped jobs. If legacy queued jobs remain after an upgrade, restore the prior runtime to drain them before continuing. No maintenance operation may hold a platform row and then acquire an unowned job row: take the public `JobsService.lockScope` barrier first, drain/check jobs, acquire job rows before actor/platform rows, then perform the generation CAS.

Shared auth pauses require explicit credential-scoped `auth_failed`, `challenge_required` or HTTP 401 evidence. Source-protected/not-found responses, media failures and unknown 403s do not invalidate a platform credential. Rate-limit cooldowns only extend, with a bounded Retry-After or a 15-minute default. Deferrals preserve the attempt budget and store a future wait; business progress exposes only counts and a small waiting-reason vocabulary, while generation/error detail remains behind `system:manage`.

### Credential maintenance in production artifacts

The normal server build includes `dist/ops/source-credentials.js`; both `runtime` and `gallery-runtime` already copy `dist`. After old source/account leases drain, invoke `node dist/ops/source-credentials.js activate <x|pixiv> <expected-generation>` from the server runtime directory. For a container installation, `docker exec <worker-container> node dist/ops/source-credentials.js activate <x|pixiv> <expected-generation>` runs against the worker's existing environment and read-only credential mounts. A one-off maintenance container must receive the same database environment, `GALLERY_DL_*` absolute paths and config/cookie mounts at exactly the worker's paths. The fingerprint includes those runtime paths and material; a host checkout with different paths is not an equivalent activation environment. Full-checkout installations can use `pnpm --filter @comiku/server source:credentials` after the server build.

The command constructs only the database, Jobs scope helper and platform-state service. It does not initialize AppModule, source/model adapters, Python or image assets. No development dependency or optional Python is added to the default image. `node apps/server/scripts/test-source-credentials-runtime.mjs` after compiling the server verifies the copied compiled CLI and activation dependency closure from an isolated runtime folder without source files, AppModule or adapter assets; it performs no database/network access.

Manual multi-target reconciliation must lock all sibling job rows before the first terminal settlement aggregates and locks their run. Otherwise exhausted A can hold run R while waiting for job B, while B's completion holds job B and waits for R. Keep job locks ahead of run aggregation even when most siblings prove nonterminal after the lock.

## Session activity

- Observe trusted visible input during capture so editor gestures that stop bubbling still renew activity; remove listeners with the matching capture flag.
- Authentication reads never touch idle timestamps. Explicit trusted visible input renews through the protected activity endpoint, with no timer heartbeat. Keep the minimum interval from the auth response through profile cache updates, and do not let a stale activity 401 clear a newer login.
- Session renewal takes a shared account-administration barrier, then its own session row lock, and samples time afterward. Administration/issuance uses the exclusive barrier; revoked, disabled, idle-expired or absolutely expired sessions cannot revive. Throttle conditional writes even across tabs, without serializing unrelated session renewals. Short idle settings need subsecond intervals and activity-specific rate buckets rather than consuming ordinary business-write limits.
- PostgreSQL transaction `now()` can predate a wait for the administration lock. Explicitly stamp session creation, last activity and absolute expiry together at actual issuance time; never inherit a transaction-start idle timestamp for a new session.

## System management sections

- System management uses `/settings/system?tab=<section>` with `collection` as its default (the parameter may be omitted). Keep the source panel in `SourceManagement(enabled)` so other management sections can compose it without moving source state or duplicating requests. Gate both source capability reads and history polling when the panel is inactive; hiding a DOM panel alone does not stop queries. Preserve mounted panels when their forms have unsaved drafts, and keep the administrator check outside the panel mount. Only register sections that are actually delivered; connection availability is not proof of successful credential validation.

## R2 signed browser uploads

- Keep returned checksum metadata headers in the presigned request's signed headers (`unhoistableHeaders`), and explicitly sign the returned content type. Hoisting checksum metadata into query parameters while also sending the header can fail R2 signature validation; removing the header may instead lose the stored metadata and break adoption. This metadata binds the declaration only: worker content hashing and media inspection remain mandatory. CORS preflight success alone does not verify a signed PUT, HEAD metadata or subsequent signed read.
- Workspace build, typecheck and test scripts each generate Prisma code. Run those generation steps sequentially in one checkout; concurrent generation can race on the same output directory. Independent checks that only read generated code may run in parallel.

## Bounded collection and analysis recovery

Terminal analysis maintenance must match failed jobs to queued analyses before applying its batch limit. A paused historical queue must not hide newer exhausted incremental jobs. Keep the per-row scope/job/candidate fences after selection; the isolated PostgreSQL regression covers more than one full batch of paused history.

Pixiv directory fallback details must pass the same future-window deferral as batch metadata. A future item written into a successful baseline can disappear permanently when its ID falls outside the bounded recheck prefix. Test a second window, including an initially empty `none` window, rather than only asserting the first page.

Pixiv profile resolution uses the native App API without enumerating works, but still needs the same rate-limit wait guard as collection. Native 300-second throttling sleeps must become `rate_limited` before the bounded profile subprocess times out; retain ordinary request pacing. Native mocked-429 tests must exercise `user_detail` rather than replacing `_call` and bypassing its wait path.
