# Development handoff

This tracked document records reusable implementation constraints. Business rules live in [architecture](../architecture.md), configuration in [configuration](../configuration.md), and visual rules in [DESIGN](../../DESIGN.md). Keep machine addresses, credentials, real samples, local experiments and deployment session notes outside the public repository.

- Fingerprint decoding limits are resource-policy failures, not evidence of a corrupt original. Map Sharp's pixel-limit rejection to `pixel_limit`, retain exact-file matching, and test that distinction with a synthetic oversized image. Do not relax the decoding budget or change fingerprint identity merely to clear historical failures.

## Work file archives

- Archive previews are estimates. Capture immutable monthly manifests and source-file references in a repeatable-read transaction; adopt that staged month under a separate short job/run fence. Do not hold or later lock a heartbeat-updated job row inside the long snapshot transaction. Annual captures are month-consistent, rather than one global annual instant.
- Read only adopted work images and the current adopted typeset version. Resolve TXT from validated work-owned rendered/handoff versions before saved entries; encoding failures are visible partial failures. Reuse LabelPlus encoding without submitting text, starting a handoff or changing workflow state. Keep metadata and text budgets bounded before materializing bodies.
- Archive source pins participate in the ordinary FileObject purge check. Preserve pins and attempt receipts while an owner is physically unsettled; an expired lease does not prove that a request or process stopped. The production stopped-owner command records an explicit operator attestation after independent shutdown verification.
- Complete intent, expected bytes and SHA must be durable before completing multipart upload. Reconcile an uncertain completion against the exact attempt identity. A database commit reply can also be lost: failure cleanup must recheck the durable package adoption link and preserve adopted objects even when a later lease or permission check fails. Only confirmed terminal archive deletion may remove adopted ZIPs.
- Keep archive generation in its opt-in worker scope with bounded buffers and lazy TXT reads. A separate queue does not isolate network, CPU or memory. ZIP64 acceptance requires real streamed bytes and extraction/checksum validation, rather than large metadata values alone; synthetic throughput does not establish real object-storage performance.
- Bandwidth zero means unlimited. Bind settings and file-deletion confirmation to revisions; retain an idempotency key after an uncertain response. Deletion removes only export artifacts, retains history and exposes retryable failures. Recheck terminal status and expiry under the run lock before automatic cleanup; a concurrent retry may have invalidated an earlier expiry scan.
- Native dialog effect cleanup must close the dialog before restoring its opener. Under React StrictMode, leaving the modal focus trap active can make the next effect capture an internal button and prevent focus restoration; verify Escape and close behavior in a real browser as well as DOM tests.

## CI and regression scope

- Seed and remove large PostgreSQL fixtures in bounded statements while retaining the complete dataset and all query-plan budgets. A single large DELETE can exceed the driver budget during foreign-key checks even after every measured query passed; track fixture identities and batch cleanup too. For history rows, use each batch's global sequence and the unique event-key join rather than repeatedly scanning and splitting the full event table. Do not increase production query timeouts to accommodate fixtures.
- Full CI runs on pushes to `main`/`dev` and on pull requests to any branch. Keep PR targets unfiltered so stacked reviews retain checks; ordinary feature pushes do not duplicate the PR run. Run affected tests during small iterations and complete the required checks before review or release.
- Consolidating overlapping tests must retain distinct behavior: the notification mask matrix also checks exact heading placement, actor labels and missing metadata; history pagination also checks explicit filter application, refresh with an unsubmitted draft, page reset, back navigation and stale-request cancellation. Keep permission, concurrency, retry, compatibility and database-plan regressions.

## Personal and administrative settings

- Personal settings are ordinary pages entered from the sidebar footer, without an overlay/background router. Keep QQ editing only within the member's profile and redirect legacy QQ URLs there; redirect the old account-management route to the system accounts tab while preserving unrelated query parameters and hashes. Mandatory password changes must retain the validated login return target; ordinary password changes stay on their page with feedback.
- Account management is a permission-filtered system tab, independent of technical settings permission. Pause roles, users and audit queries while hidden, keep loaded form drafts, check audit permission separately, and unmount any native administrative dialogs while the tab is inactive. Ordinary members must never trigger account-management reads through a direct URL.
- Personal avatars reuse ImagePicker's avatar variant and opt-in avatar formats, preserving GIF alongside PNG/JPEG/WebP, the 5 MiB limit, empty-file rejection and the existing revision-checked upload/cache protocol. Keep default image/source format sets unchanged and use local previews until an explicit save.

## Notifications

- Birthday display and reminder editors share a complete settings DTO and revision, but own different fields. Keep scoped drafts with their original revision; compose unowned fields from one current server snapshot. Conflict adoption must retain only owned edits and use the latest unowned fields/revision, without automatic resubmission. When no draft exists, take both owned fields and revision from the same snapshot. A hidden observer must cancel an exact shared query only after confirming no active observer still needs it; inspect observer state after registering the current query options.
- Keep notification-wide module controls in the section heading and per-channel subscriptions beneath channel identity. A settings tab that contains both scopes must be named accordingly; moving a control must preserve its save boundary, draft and revision semantics.
- Notification failure diagnostics are transient structured logs, not schema/API fields. After a non-accepted attempt is durably settled, `notifications/delivery_settled` records ledger IDs, attempt number, controlled status/error code and only validated numeric HTTP status/OneBot retcode; unknown retcodes retain the existing unknown/no-auto-resend policy. Never spread adapter diagnostics or log raw responses, message bodies, contacts, group numbers, tokens or URLs. `work-reminders/digest_capacity_exceeded` records channel/slot and scalar item/mention/text-code-unit/budget metrics before registration, without serializing an extra oversized payload; it consumes no slot or notice. Test privacy canaries and suppress settlement logs when the ownership/commit fence fails.
- Task handoffs use independent `work.ready` events and the existing per-participant/round/kind/channel notice ledger, rather than daily digest slots. Serialize registration per channel, freeze one current task per message, and reuse reminder send-time checks. Keep accepted, unknown, unrouted and any crossed-send-boundary notice consumed across subscription generations; a conclusively unsent cancellation/failure is reusable only when all deliveries of that event/channel are conclusively unsent. Reclaim only the selected identities with indexed lookups, never sweep a channel's full notice history every minute; the handoff path does not need a full candidate count.
- A claim and upstream submission can occur between observations. Recover an initial future-stage owner claim only from matching durable claim evidence, including its exact `participantId`, work, user, stage and operation. Do not infer that link from matching timestamps: Prisma may supply different millisecond defaults within one transaction. Do not reuse an initial claim to qualify a later cancellation, assignment or contribution round, or backdate the overdue clock.
- Scheduled digests contain stage backlog totals, the unclaimed subset and every currently eligible overdue detail. Handoff messages are separate from `work_digest` occurrences and ignore digest send slots; both resource kinds require the same structured-contact validation and prohibit replaying historical mentions. Preserve old frozen digests and their validation compatibility.
- Full-list digests use snapshot format 3 and derive their extended transport policy only from a valid `work_digest` resource/snapshot. Do not take limits from routeRefs or client input. Preserve the standard policy for old digests, handoffs and other notifications; use a 256 KiB escaped UTF-8 request budget for full digests instead of task/mention counts. A capacity failure must consume neither the slot nor notices and must not roll back already registered handoffs. Evidence hydration, globally ordered work/user locks and notice writes use batches; each full digest still contains the entire current list.
- A format-3 slot may be rebuilt only when all sibling deliveries were cancelled for task change or stale observation and no attempt crossed the send boundary; verify every frozen audience/settings/subscription generation under the existing locks. Preserve the old event as history and use a new event identity. Accepted, unknown, failed, queued or sending siblings must continue to block a replacement.
- Work digests are independent opt-in subscriptions and occurrences, not WorkEvent types or business-transaction callbacks. Match "available" counts to actual claim ownership: an inactive or unqualified existing owner still blocks a new claim until business rules release that ownership.
- Reminder clocks are conservative observations. A single persistent heartbeat counter excludes unknown downtime; each episode records its counter checkpoint and business evidence. Do not cap elapsed time by each episode's scan interval: bounded rotation otherwise permanently stops clocks when activity exceeds a batch. Changed evidence discards the uncertain interval; assignment/cancellation/completion boundaries create a new round. Batch episode writes and select live rows separately from ended history; check actual SQL scan work with large historical fixtures.
- Freeze an occurrence under the projection's shared advisory lock and use its latest observed time. A second worker can advance the projection after the first worker's timestamp; filtering those newer observations then recording an empty occurrence loses the entire slot. Test that exact interleaving, not only identical-time concurrent calls. Advisory functions returning PostgreSQL void must use executeRaw or an explicit supported result cast.
- Notice ownership follows only displayed items. Accepted, unknown and any crossed send boundary cannot be silently moved to another slot. Conclusively unsent cancelled/failed items may return. Expiry updates must recheck status in their outer UPDATE predicate after a row-lock wait so they cannot cancel a concurrently reserved sending attempt.
- Freeze structured at segments from self-declared contacts, with source identity and user revision. Check frozen text/segments/contact equality, current task evidence and clock immediately before send reservation; acquire short business shared locks with NOWAIT to avoid a cross-module wait cycle. Network calls happen after commit. Never parse CQ text, permit at-all, reveal raw contact payloads through history DTOs or replay old digest mentions.
- Work reminder previews use the backend formatter with debounced, cancellable draft requests. Keep panel-specific query keys and disable hidden requests; template Edit must focus and scroll to the actual editor. New API declarations must be reflected in generated OpenAPI/client artifacts.

- QQ reminder contacts use dedicated self-only GET/PATCH endpoints rather than extending `ProfileDto` (also inherited by admin creation/management) or the shared `UserDto`. Keep nullable unique QQ values out of auth/member/admin projections and audit detail; record only whether a binding exists. Recheck the session under the account write lock, enforce expected profile revision and map the QQ-only update's unique conflict separately from username conflicts; driver adapters do not guarantee a `P2002.meta.target` array. A current-revision same-value update is a no-op; stale writes still conflict. This is a declared contact, not verified QQ identity or a login mechanism. Structured mentions require a separate delivery contract; plain text/CQ strings must remain inert. Read/retry buttons inside forms must explicitly use `type="button"`; cached data plus a failed refetch must never submit a dirty binding draft.

- Quarantined accepted SchaleDB entries retain display facts but must disable new reminders even after the source check succeeds. Recompute eligibility from accepted membership; pending unaccepted outfits must not veto a trusted person. An outfit's old hint for an already accepted pending original is not a fresh review and must not reject the entire source. A reverted source stays held until explicit review.
- Birthday summary/calendar caches also expire when a hidden or disabled panel resumes on a new Shanghai date within the normal stale window. Keep each key lazy and avoid restarting an in-flight read; same-day resumes retain fresh data. Exercise short hidden-midnight transitions as well as the visible midnight timer.

- Birthday workers drain due Kivo checkpoints without batch sleeps, while reminder maintenance, primary-source scheduling and failed cleanup retain independent one-minute cadences. Source/job retry eligibility is persisted for five minutes; a terminal job's future eligibility must also fence replacement scheduling. Register the birthday handlers' retry delay with Jobs: changing only source `nextCheckAt` does not delay retries of an existing queued job. Keep ordinary Jobs backoff unchanged, preserve attempt limits and test restart/reclaim behavior against PostgreSQL.

- Birthday source evidence is independent: a successful Kivo index cannot renew profile birthdays, and a successful SchaleDB check cannot renew Kivo people. Publish source facts and the combined catalog under the same combined-state mutex; profile hashes bind freshness to the exact persisted evidence. Every source writer, including index membership registration, takes job lease then combined lock then source-state lock. Keep source raw catalogs separate from public projections.
- Public birthday person keys survive a later explicit game-ID bridge; persist accepted skin/game membership even when upstream edges disappear. Names only hold suspected duplicates, never merge identities. Keep the historical date/offset occurrence namespace and event key: a frozen daily digest is not regenerated after profile recovery, discovery or implementation. Source fetch failures must not skip DB-only reminder maintenance.

- Birthday digests use their own resource kind, UUID occurrence, hash and frozen content. Never add a default discriminator to legacy work receipt JSON: v1/v2/v3 identity and key order must stay unchanged. Birthday global/offset/group-subscription generations cancel only birthday deliveries; they must not mutate the shared channel's work generation. Check global, offset, group scope and channel activation cutoffs against the frozen due time, including routing, pre-send and explicit replay. The deployment feature flag must guard all three paths.
- A notification target may be enabled with zero work events for birthday-only subscriptions; zero work rules must capture no work events. A template preview is synthetic and does not send. Expired birthday digests stop at the sending day's boundary, while existing work delivery recovery retains its prior policy.
- Preserve confirmed birthday identities across refreshes, including a newly reviewed original-entry ID. An original entry must be confirmed as belonging to that same person; never accept an arbitrary cross-person avatar or infer a person's identity from a similar name. Normalize overridden aliases before hashing so repeated unchanged refreshes do not produce new catalogs. Validate persisted names as well as fetched names before rendering notifications.
- First-discovered people without a valid localized name remain `unlocalized`, without a fabricated translation or published person. Persist their canonical key and all entry members; restored localization may publish that same identity. New cross-person edges or inconsistent birthdays move the whole held group to `pending`, retaining its boundary even if the edge later disappears. Never normalize an unknown persisted status to `confirmed`; share the provider's status validator. Existing published-name failure still rejects the replacement catalog.
- Birthday summary/calendar queries need one visible-page invalidation at Shanghai midnight, without regular polling. Keep full-calendar fetch lazy, make long same-day lists horizontally reachable and respect reduced motion. Explicitly set non-submit form buttons to `type="button"`, particularly revision-conflict controls: implicit submit can send the stale revision while adopting the new one.

- Event-template messages use an explicit Asia/Shanghai clock to seconds and place an enabled title beside the work number. Describe each event's action instead of appending generic workflow/review-state rows. Content review decides whether production should continue; it is separate from proofreading quality or returning a translation. Whole-stage submission, personal completion and saving a typeset version must remain distinct. Reserve the complete action, URL and replay prefix before truncating optional Unicode metadata. Legacy messages and already-frozen text retain their original layout; previews and new captures share the formatter.
- Capture input version 3 adds only a safe optional claim/join discriminator for participation events. Derive it from an exact known durable operation shape with the matching stage; unknown historical forms use neutral language. Keep versions 1/2 strict allowlists, JSON key order and hashes unchanged, require frozen route content for versions 2/3, and distinguish input versions from route format versions. Never reconstruct frozen receipt/delivery text from current templates or metadata.
- Respect title, author and actor switches independently, including names embedded in action sentences. Preserve existing explicit settings and the all-hidden missing-template policy; suggested display choices must be saved explicitly. Event subscriptions control notification handling without changing business events or the workflow. Tests should exercise claim versus collaboration, every visibility mask, missing metadata, legacy registration and Unicode/replay limits.
- Supported PostgreSQL versions may choose different bounded index or bitmap/skip scans. History performance assertions should constrain the indexed status predicate and actual scan/sort work rather than require a sparse query's index name. Include removed filter/recheck rows and loops, and test heap work and sort inputs hidden behind LIMIT; accepting another valid plan must not permit sequential scans or increase the original budgets.

- Template auto-preview shares the server formatter and runs only for the visible editor. Cancel timers/requests and fence success, error and finalization by the same draft epoch; same-value selection must not invalidate a preview without retriggering it. Keep drafts and observed revisions separate from refreshed configuration. A nested open selector consumes Escape before the native editor closes; focus and background scroll return to their original state.
- History pages bind every normalized filter and page size into an opaque cursor, select immutable delivery group IDs, and resolve work numbers through the unique Work lookup rather than JSON scans. Keep one page mounted; applying filters or refreshing returns to the first page. Date inputs use local calendar boundaries with an exclusive following-day end, including daylight-saving transitions. New rows and status changes do not provide a snapshot-pagination guarantee.
- Outgoing queue metrics are separate from source-reconciliation counts; resolved failed/unknown records must not remain actionable. Limit metric samples and verify actual PostgreSQL plans against large resolved histories, large active backlogs and equal timestamps rather than assuming LIMIT bounds work. Preserve the constrained leading group/status key in cursor seeks so compound indexes can serve deep pages.
- Synthetic previews, saved template samples and connection tests must not link to nonexistent works. Real business messages keep their true UUID destination and stored historical text stays immutable. Authentication and mandatory password changes preserve only a validated application return path, including its query/hash; they never trust a raw external history-state target or weaken the destination's permissions.

- Expand notification coverage from actual WorkEvent producers, not every historical enum value. The active catalog includes 24 actions; historical review-revision/assignment enums without a producer remain unsupported. Whole LabelPlus imports in multi mode require an admin participant; page assignments cover translate/proofread, not typeset. Exercise these real rules in HTTP fixtures rather than weakening business checks to make notification tests pass.
- Persist a separate activation for newly supported actions and retain the original source boundary. Keep legacy and expanded partial indexes/ranges separate: a combined OR scan can repeatedly visit pre-expansion history left intentionally unconsumed. Bound each range before merging candidates or count samples; exercise real SKIP LOCKED, same-resource registration heads and old-history query work. One maintenance pass only registers the earliest active receipt per resource; regression tests must drain bounded passes and clean each subcase even on failure.
- Notification status is worker maintenance evidence, never bot connectivity or delivery confirmation. Observation writes run once per maintenance outside business transactions and cannot block routing on errors. Cap each admin count at 1000 with an explicit overflow indicator, paginate receipt allowlists, and do not scan work sources while disabled/uninitialized. Only the active status summary polls; loaded receipt pages do not accumulate periodic refetch work. Preserve dev's SourceManagement (connections plus history) when integrating notification tabs, and pause both capability/history queries while hidden.

- Work lifecycle notifications reconcile existing durable WorkEvent rows asynchronously; do not inject the publisher into business transactions to make notification registration another business success condition. The source marker is Prisma @ignore and raw-SQL-only, keeping default business event reads/DTOs unchanged. Use the pending partial index, a persistent activation boundary and independent receipts, not timestamp/UUID consumption high-water marks.
- Capture source marker/receipt atomically, then register notification event/receipt atomically. Freeze safe source facts, payload hash and destination generation; transient DB registration errors retry with bounded delay and deterministic invalid inputs are isolated. WorkEvent has no historic revision/sequence: receipt ordinals describe bridge capture order, not recovered business causality. Display metadata can be read at first successful capture with explicit capture_current origin and observation time; do not describe it as historical names, and never rehydrate on retry/replay. Keep v1 receipt allowlists and hashes unchanged; validate new v2 content explicitly.
- Channel source eligibility advances only with real delivery generation changes, not renames/no-op saves. Uncaptured old-generation backlog may be conservatively skipped; captured intent retains its original audience. Source timestamps define qualification, not exact commit visibility. Extra partial-index/WAL work is bounded overhead, not zero physical database cost.
- System management uses collection/notification tabs and group/template/history sub-tabs with inactive queries paused. Keep visited editors mounted so switching tabs does not lose drafts; mutation completion must invalidate active observers rather than explicitly refetch a hidden panel. Connection availability describes configuration validity, not bot online state. Shared event templates have independent title/author/actor flags; legacy groups require explicit adoption.
- Content revision, editor revision and audience generation are distinct. Template edits and mode adoption retain existing pending text and source cutoff; event/stage subscription or target changes cancel the group's entire old pending generation. Freeze resolved content per recipient, not once per Event: a legacy recipient must never inherit display metadata merely because another group uses a new template. Capture policy reads and template updates share a short database lock; never hold it during external requests.
- Historical replay copies the original body with an idempotent replay marker; it does not use current templates. Reserve the marker budget in new messages, preserve full links, and explicitly reject a legacy body that cannot fit safely. Draft/sample previews use synthetic event facts, and actual saved samples must check both channel and template revisions.
- A confirmed sample must retain its previewed target, mode, stage and revisions; refreshed props cannot silently advance the revision submitted with old consent. Legacy adoption previews also depend on every selected saved template revision. Invalidate displayed and in-flight consent when that context changes. For both group and template 409 recovery, retain the draft and offer explicit current-version comparison/reapply; refresh alone must not silently rebase or leave an unsaveable stale revision forever. Explicit template Edit should focus its editor so the form remains discoverable on narrow screens.
- Legacy-to-template adoption must send the complete previewed `expectedTemplateRevisions` set, including default revision 0. Validate it in the adoption transaction while holding the template advisory lock before the channel row lock; a channel revision cannot detect a concurrent template edit. A stale template returns 409 without adopting, cancelling pending deliveries or advancing the source boundary. Retain the field draft and require fresh confirmation; invalidate active query observers rather than forcing a hidden panel to refetch. Exercise both actual PostgreSQL lock orders with barriers and observed ungranted advisory locks.
- Delivery history must expose its frozen group ID and safe connection key, independently of the current Channel name/target or whether that connection still exists. Do not reconstruct the old destination from current configuration or expose endpoint, credentials or connection fingerprints.
- Do not run Prisma generation concurrently with another process type-checking its generated directory; replacing those files can produce transient TS6053 errors. Generate once, then run dependent checks. Tests injecting transaction faults must wrap transaction delegates, not only root delegates.
- Select each resource's earliest active receipt before filtering due time. A deferred head plus many due followers can make a NOT EXISTS anti-join quadratic despite LIMIT and indexes. Test actual query work with synthetic backlog and EXPLAIN ANALYZE, not an exact index/plan name or wall-clock threshold. Head-first selection still scales with active backlog and leaves room for a dedicated head index/store if needed.
- PostgreSQL truncates identifiers at 63 bytes; use explicit short maps for long receipt indexes so Prisma drift checks agree with deployed names. Transaction callback delegates do not inherit a root Prisma delegate monkeypatch; inject inside the transaction to prove capture/registration rollback rather than testing a mock that was never called.
- Record source identity, payload hash and the destination/configuration snapshot together. Configuration disable/re-enable advances its generation; asynchronous routing must preserve the old target for audit and refuse to send it to the new audience. Idempotent replays retain the first subscription snapshot.
- Jobs owns leases; Delivery/Attempt owns the external-send boundary. Never let generic job retries resend an unresolved sending attempt. A final expired lease can retire a job without invoking its handler, so bounded reconciliation must settle abandoned sending records as unknown. Unknown and other unresolved intent do not expire automatically.
- External HTTP runs after the reservation transaction commits. Recheck current channel/version and privileged test/replay actor before reserving; do not hold channel, delivery or work locks across network latency. A shutdown/permission change cannot recall an already in-flight request.
- OneBot HTTP 200, async status and an absent message_id are not successful delivery receipts. Encode user text as text segments, restrict connection destinations at DNS and dial time, retain HTTPS validation and never follow credential-bearing redirects. Protocol receipt is not member read confirmation.
- Keep optional configuration isolated from offline OpenAPI export and normal application construction. Disabled notification loops perform no notification polling or bot probes; close adapter pools when the application closes. Test only synthetic endpoints unless a dedicated real destination is explicitly authorized.

## Author creation

- Submit the base author fields and distinct-platform account identities in one database transaction. A failed account binding must roll back the author, tags and earlier account inserts. Keep provider/profile requests and image transfers outside the transaction; X identities require server-verifiable profile evidence.
- Creation retries use an actor-scoped UUID and a canonical hash of the saved business fields. Commit the request record and author together, serialize concurrent requests, reject changed payloads under the same key, and recheck current source/admin permissions inside the transaction. A committed replay must not depend on the original profile proof's expiry or provider timestamps.
- Keep the same request ID when a POST response is lost, and inspect the actor-scoped creation-result endpoint before assuming no author was saved. A missing result can race an in-flight transaction and never authorizes automatically replacing the key. The browser stores only this opaque request ID in session storage; drafts, proof tokens and files remain in memory. Reopening the same browser tab can recover a committed author, while unsaved text/files require re-entry. Closing the tab ends that browser recovery boundary.
- Creation action failures use a nonmodal top-layer toast: an ordinary body portal can be hidden behind the native author dialog or made inert by it. Do not steal focus or require confirmation. Expiry clears only the error, never the parent dialog, creation request ID, selected files or upload recovery state. Pause expiry while hovered, clean up timers on replacement/unmount, and allow identical failures to appear again on an explicit retry.

## Author management notes

- Account binding/restoration must lock and recheck the active parent author before account writes, in the same author-to-account order as archive. A prior read outside that lock can create an active account after the author was archived. Author deletion in the UI is the existing archive operation: pin nickname/revision when confirming, require the exact nickname, retain works/history, and leave restoration to the existing administrative backend.

- Author forms keep tags as choices, not comma-delimited text. Existing choices submit immutable tag IDs with their observed revisions; explicit new names are separate. Resolve references before any author/tag-link write and reject stale or removed references rather than recreating their names. All catalog/link writers, including the whole CSV batch, take the same short transaction-scoped catalog mutex before tag/author rows; ordinary reads do not. Batch new-name insertion and lookup instead of per-tag round trips. No provider or file network request belongs inside this lock.
- Keep the original creation hash algorithm for committed legacy name-format replays only. New intent hashes use sorted reference IDs/revisions and normalized new names, without consulting current tag names; replay committed results before revalidating the catalog. Old-format uncommitted writes require a page refresh. CSV preview pins references and commit validates them; strip preview-only errors before nested request validation. Enforce both display-name and normalized-name column limits, since Unicode lowercasing can expand a name.

- Author/account notes are nullable plain text with a 2000-character request limit. Preserve omitted PATCH fields and normalize explicit blank/null to SQL null; source profile refreshes must not erase an omitted note. Notes share the existing author/account revision fences and do not create an additional history store.
- Keep notes in `ManagedAuthorDto`/`ExternalAccountDto` only. Public author, list, candidate and account-summary serializers must remain explicit allowlists. The management form reads `/authors/:id/managed` under `authors:manage` and uses its own query cache; never populate a public-author cache with a managed response.
- Historical author-creation hashes excluded notes. Add hash keys only for nonempty normalized notes at both author/account levels, so old committed requests replay unchanged. Blank/null/omitted notes must hash identically; changing a nonempty note under the same request key conflicts.
- Dirty notes follow the metadata form baseline and survive background refresh and failed attachment retries. A failed public or managed background read must retain the cached editor and upload state, with a nonfatal retry status; an error-only page wrapper would unmount the form and discard both. A clean newer managed snapshot may hydrate notes; only explicit load-latest discards dirty fields. The synthetic notes integration test requires the usual disposable `_test` database and exercises HTTP role/privacy, revision, persistence and old-request compatibility; unit/UI checks alone do not certify a migrated database or browser layout.

## Candidate review editing

- Image adoption and source ordering are different facts. Import the ordered subset atomically with the selected candidate revision; never save the candidate media order first. Retain all source media/file references, and map each WorkImage to its exact CandidateMedia ID rather than only its file ID (a source can reuse a file on different pages).
- New import replay compares the original pre-import revision and ordered provenance IDs before returning the existing work. Current WorkImage identity/order has no mutation path; adding such a path requires an immutable import receipt before changing this comparison. Preserve legacy omitted-request replay; do not invent a revision or an adopted=false result for unknown legacy provenance. Backfill only an exact source-post/order/file match.
- Source inspection is lazy and follows works:read, including unselected source media. URL signing must recheck work-to-source-post-to-media binding, not accept an arbitrary candidate media ID. Return only safe source DTO fields; candidate metadata may later be enriched, so distinguish its current text from Work.sourceText's imported snapshot.

- Candidate import locks the observed author with `FOR SHARE` before locking the candidate with `FOR UPDATE`, then re-reads both the binding and business state. Require current authorization and an active author before creating a Work; a concurrent reassignment conflicts rather than checking the old author. Preserve imported-request replay and per-item batch outcomes. PostgreSQL regressions cover mutations after the initial read and author updates blocked by a valid in-flight import.

- Author suggestions debounce their own paginated reads; only explicit single-author confirmation changes the review scope. Keep draft input separate from the selected author ID and consume cancellation signals so late searches cannot replace current suggestions.
- Keep per-post ordered image-subset drafts and their original revisions at page scope, independently of membership snapshots and panel mounts. Applying an adjustment is local; only final import writes the subset. Ordinary model refreshes do not discard drafts; real media/version changes require explicit reset. Reset must remount local editor state even when the freshly read revision equals the already open editor's revision. Batch completion only settles the same selection generation and draft version. An uncertain response freezes the exact manifest for replay, including after closing and reopening confirmation. Warn on route departure or hard refresh, without promising browser-close restoration.
- ImageLightbox can portal into an active native dialog, with top-preview Tab/focus/Escape ownership and connected focus restoration. Suspend its keyboard/focus trap when another native modal is above it, such as the draft-leave confirmation; otherwise the hidden preview can capture that dialog's keyboard. Share one visibility observer for image thumbnails and sign originals only for the current preview. Work source reads and bulk-confirmation image expansion remain lazy.

## Author attachments

- Evidence reads distinguish loading, failed reads and confirmed empty results; keep cached evidence visible on a failed refresh. Removal confirms a pinned author revision and does not change authorization status.
- Manual candidate upload keeps per-group checkpoints after each order/metadata response and each successful batch import. Retry only unfinished steps at their returned revisions, including when another group fails; imported groups cannot block retries if their author selection later becomes unavailable. Require explicit initial author selection, and retain ZIP/GIF support and source-specific limits when reusing the file picker.

- Direct-upload admission lasts 24 hours, independently of accepted jobs and terminal receipts. A matching queued/reclaimable or live leased job protects its staging after that deadline. All adoption transactions lock and validate their job lease before actor/resource rows, then complete the session atomically. Reconciliation and cleanup must never regress a terminal state. Finalization samples its deadline after the session lock.
- Keep terminal receipts for seven days from first terminal time. Delete staging in two phases: after a 15-minute write-grant grace, then before receipt removal; failed passes retry idempotently without dropping keys. A successful cleanup pass does not prove an already in-flight external PUT cannot finish later. Terminal DTOs expose no manifest; the retained manifest contains only keys after cleanup. Exclude direct-upload staging from bucket age-based lifecycle rules before upgrading.

Range-filter vector values before summing too: two individually representable 9e131071 numeric values overflow their sum even when the separate validity flag is false. Synthetic PostgreSQL fixtures cover missing vector fields, scalar drift, current-SHA checks, rule edits between snapshot read and materialization, frozen explanations, and legacy classification cleanup without changing modern model or human review data. These checks do not establish production throughput or real-model accuracy.
- Scope candidate IDs before aggregating tags and image results. Use set-based joins for source tables, materialize the bounded per-image validity projection once, and reserve LATERAL for each image's bounded vector. Correlated table scans can degrade after bulk ingestion with changing planner estimates; increasing the production query timeout is not a routing fix. Session-page live classification projections must use only that page's candidate IDs. The 50,000-post synthetic check uses one image and two tags per post; it does not establish capacity for arbitrary image counts or concurrent reviewers.
- Analysis refreshes may update cards within the same review session, but must not exchange section membership or ordering. Only explicit refresh, expiry or model/filter mismatch establishes a replacement snapshot. Coordinate active-card refreshes and a final read after queued work settles, pause background polling, and clean up timers/subscriptions without clearing cross-page selection.
- Keep the hashed BA extraction/pipeline/processor files byte-identical. Formatting these files changes their artifact identity. Preserve third-party license and attribution files when packaging runtime assets.
- Exact-byte runtime artifacts need path-level `-text` Git attributes as well as formatter exclusions. Check staged blob SHA-256, not only working-tree bytes: line-ending normalization can otherwise make a fresh Linux checkout fail the runtime integrity check.
- The BA runtime reads model paths from its process environment, explicit CLI flags or an optional JSON configuration; JSON-relative paths resolve against that configuration file. Model artifacts can remain outside the checkout, with no required repository directory. The runtime does not read executable code from a model directory or require training tools.
- Reuse a resident model with bounded handlers, one inference lock and a measured CPU thread budget. HTTP disconnect does not cancel an in-progress PyTorch call; shutdown must drain accepted work before removing hooks.

## Verification and operations

- Keep the three work perspectives in one navigation component. Series browsing has its own query and must not mount or fetch the ordinary work list or its stage/layout controls. Save the current work query before leaving for series and carry it through the directory/detail/back links; restore the work filters/layout on return without turning series into a backend WorkView enum.


- Similarity searches scan only originals referenced by WorkImage. A candidate fingerprint created by an explicit lookup must not expand the adopted-image scan or coverage counts. SHA matches remain useful when perceptual decoding fails. Version the normalization recipe; never interpret perceptual distance as proof that comic dialogue is identical. Check SQL plans and response timings separately from an in-memory XOR/popcount benchmark.
- Keep history fingerprint backfill in the existing heavy/global slot, cap outstanding work across workers and yield to other eligible heavy jobs. Empty-history discovery is throttled; a LIMIT does not bound the cost of proving every original is already covered. Interactive GETs must not repair or enqueue jobs.
- Candidate import series intent is an immutable receipt, not current membership. Compare canonical values: PostgreSQL jsonb reorders object keys. Persist the normalized intent with the Work and attach membership in the same transaction; a lost reply must replay the original candidate revision, ordered media IDs, series revision and request ID. Lock/recheck the full Actor session and candidates:manage before the author, series and candidate rows; works:metadata alone also permits operators and is insufficient for candidate import.
- Album pagination is per WorkImage, not per Work. Bound cursors to actor and filters, retain actual adopted order, and keep album queries independent from ordinary Work-list loading/errors. A disabled layout must not initiate its queries. Lightbox footer extensions preserve existing Pointer Events, keyboard navigation, focus restoration and zoom.

- Background jobs default to `global` execution scope and `default` queue. Claim/runNext callers may opt into another scope without adding a lease engine. Register the same queue policy in every worker; the `(lane, scope)` advisory lock and `JobQueueState` persist its consecutive-selection budget. Queue priority and ten-minute aging apply after queue selection. After taking the job row lock, re-read full job eligibility and payload: ordinary retirement/management writers do not hold the claim advisory lock. Reject a terminal, moved, delayed, exhausted or unhandled row before gate or fairness writes. Claim gates run under the job row lock in the short claim transaction and may pin database state; keep network/model/storage work outside. A returned `JobDeferred` delays an unclaimed job without consuming attempts or fairness; a handler-thrown `JobDeferred` restores only the current claim's attempt while the same live lease remains owned, including the third claim. Deferral reasons are runtime allowlisted and both waiting paths persist at least five seconds into the future to prevent refunded-attempt hot loops. Ordinary exceptions retain the three-attempt failure policy. Scope policies and claim gates are registration APIs; adding the analysis lane alone does not move existing handlers or start another worker loop.

- PostgreSQL JSON extraction must be grouped before JSON-key subtraction: `((value->'field') - 'key'::text)`. An outer pair of parentheses alone does not prevent operator precedence from subtracting unknown string literals. Wrap a new forward migration's DDL and backfill in one explicit transaction so a statement error cannot leave partial tables behind. Exercise the actual migration against synthetic PostgreSQL history before calling deployment complete.

- Use the pinned Node/pnpm versions. Run ordinary tests with synthetic fixtures; PostgreSQL integration tests require a separate disposable `_test` database.
- Serialize commands that regenerate ignored Prisma output in a shared worktree, including server tests, server type checks and API generation. Overlapping generators can remove or partially replace each other's output and cause misleading missing-type or `ENOTEMPTY` failures. Web-only checks do not need Prisma generation.
- Do not use a distant database connection to diagnose transaction timeouts as application defects without checking network latency. Do not reset a business database to fix test setup.
- Use the optional Python environments for adapter tests. A missing gallery-dl dependency in a different system Python does not establish an adapter defect.
- Capacity and live-platform coverage require explicit environment tests. A worker heartbeat, passing fixtures or a built image does not prove every collection job succeeded.
- Short object-storage signatures depend on correct host time. Inspect time offset and source reachability separately; a running time daemon does not establish synchronization.
- Probe API readiness on its own listener before checking a dependent reverse proxy. Stopping a systemd unit may stop services that require it; explicitly restore dependent test services, and retry readiness rather than treating `active` as proof that a listener is ready.
- Test connection admission without sending unread bytes when asserting an immediate overload response; TCP reset behavior differs across operating systems.
- Build scripts copy an explicit list of public non-TS runtime assets and required notices. They must not copy private configuration, model files or tests into production assets.

Before an authorized commit, inspect the full staged diff and untracked files. Commit messages describe the problem and concrete changes only. Keep verification records, deployment notes and remaining scope in the appropriate handoff or PR description; do not include environment secrets or unrelated work.

## Platform-scoped source collection

`source_account_fetch` jobs use the `network` lane, `source:x` / `source:pixiv` execution scopes and the `scan` queue. A run persists all account targets before any job starts, and is terminal only after every target settles. The single policy registration in `SourceFetchService.onModuleInit` reserves a 3:1 scan/recovery ratio; recovery handlers must reuse that policy instead of registering another one. Scheduler/reconciliation run in a separate short loop. A waiting account reserves only itself: a completed Pixiv target may be scheduled again while an X sibling waits.

Credential identity is a SHA-256 fingerprint of the controlled gallery configuration and its referenced cookie-file bytes. Reads are bounded to 1 MiB per file and 4 MiB total. Use separate per-platform configuration files and absolute literal cookie-file paths (no shell/environment expansion). Relative paths are rejected because gallery-dl can resolve them from the worker working directory, which differs from a config-directory interpretation. All referenced cookie files in that platform config participate in the fingerprint, including inactive sections; avoid placing unrelated platform sections there. Export browser cookies to controlled files; mutable browser-profile credential stores cannot be activated. The fingerprint is checked at claim and immediately before network work. A locally mismatched worker rolls its claim back without postponing the shared job, and backs off its own scope. Only an absent shared row may bootstrap, under the Jobs scope barrier and with old source/account leases drained. Existing workers and GETs never replace a generation.

To rotate credentials, first drain running platform/global collection and source leases, update the controlled local files, then run `pnpm --filter @comiku/server source:credentials activate <x|pixiv> <expected-generation>`. The expected generation comes from the administrator-only platform endpoint. Activation is compare-and-swap and leaves the new generation `unverified`; it is not a network verification. The administrator recheck endpoint releases an auth pause for the same local generation and wakes queued work, or schedules an eligible scan when none is pending. It does not shorten a trusted rate-limit cooldown. A real, fenced successful scan establishes `healthy`. Credential-derived pauses stay in platform state, so rotation does not inherit a stale per-account credential cooldown; source/media failures retain their own account state.

Before upgrading a worker from whole-run `source_fetch`, disable scheduling and drain all queued/running whole-run jobs using the old runtime. Then stop old workers and verify global job and account leases are drained before starting scoped workers. The new runtime refuses to execute legacy whole-run handlers; it does not silently convert, discard history or run them alongside scoped jobs. If legacy queued jobs remain after an upgrade, restore the prior runtime to drain them before continuing. No maintenance operation may hold a platform row and then acquire an unowned job row: take the public `JobsService.lockScope` barrier first, drain/check jobs, acquire job rows before actor/platform rows, then perform the generation CAS.

Shared auth pauses require explicit credential-scoped `auth_failed`, `challenge_required` or HTTP 401 evidence. Source-protected/not-found responses, media failures and unknown 403s do not invalidate a platform credential. Rate-limit cooldowns only extend, with a bounded Retry-After or a 15-minute default. Deferrals preserve the attempt budget and store a future wait; business progress exposes only counts and a small waiting-reason vocabulary, while generation/error detail remains behind `system:manage`.

### Credential maintenance in production artifacts

The normal server build includes `dist/ops/source-credentials.js`; both `runtime` and `gallery-runtime` already copy `dist`. After old source/account leases drain, invoke `node dist/ops/source-credentials.js activate <x|pixiv> <expected-generation>` from the server runtime directory. For a container installation, `docker exec <worker-container> node dist/ops/source-credentials.js activate <x|pixiv> <expected-generation>` runs against the worker's existing environment and read-only credential mounts. A one-off maintenance container must receive the same database environment, `GALLERY_DL_*` absolute paths and config/cookie mounts at exactly the worker's paths. The fingerprint includes those runtime paths and material; a host checkout with different paths is not an equivalent activation environment. Full-checkout installations can use `pnpm --filter @comiku/server source:credentials` after the server build.

The command constructs only the database, Jobs scope helper and platform-state service. It does not initialize AppModule, source/model adapters, Python or image assets. No development dependency or optional Python is added to the default image. `node apps/server/scripts/test-source-credentials-runtime.mjs` after compiling the server verifies the copied compiled CLI and activation dependency closure from an isolated runtime folder without source files, AppModule or adapter assets; it performs no database/network access.

Manual multi-target reconciliation must lock all sibling job rows before the first terminal settlement aggregates and locks their run. Otherwise exhausted A can hold run R while waiting for job B, while B's completion holds job B and waits for R. Keep job locks ahead of run aggregation even when most siblings prove nonterminal after the lock.

## Session activity

- Observe trusted visible input during capture so editor gestures that stop bubbling still renew activity; remove listeners with the matching capture flag.
- Authentication reads never touch idle timestamps. Explicit trusted visible input renews through the protected activity endpoint, with no timer heartbeat. Keep the minimum interval from the auth response through profile cache updates, and do not let a stale activity 401 clear a newer login.
- Session renewal takes a shared account-administration barrier, then its own session row lock, and samples time afterward. Administration/issuance uses the exclusive barrier; revoked, disabled, idle-expired or absolutely expired sessions cannot revive. Throttle conditional writes even across tabs, without serializing unrelated session renewals. Short idle settings need subsecond intervals and activity-specific rate buckets rather than consuming ordinary business-write limits.
- PostgreSQL transaction `now()` can predate a wait for the administration lock. Explicitly stamp session creation, last activity and absolute expiry together at actual issuance time; never inherit a transaction-start idle timestamp for a new session.

- System management uses `/settings/system?tab=<section>` with `collection` as its default (the parameter may be omitted). Keep the source panel in `SourceManagement(enabled)` so other management sections can compose it without moving source state or duplicating requests. Gate both source capability reads and history polling when the panel is inactive; hiding a DOM panel alone does not stop queries. Preserve mounted panels when their forms have unsaved drafts, and keep the administrator check outside the panel mount. ## R2 signed browser uploads

- Keep returned checksum metadata headers in the presigned request's signed headers (`unhoistableHeaders`), and explicitly sign the returned content type. Hoisting checksum metadata into query parameters while also sending the header can fail R2 signature validation; removing the header may instead lose the stored metadata and break adoption. This metadata binds the declaration only: worker content hashing and media inspection remain mandatory. CORS preflight success alone does not verify a signed PUT, HEAD metadata or subsequent signed read.
- Workspace build, typecheck and test scripts each generate Prisma code. Run those generation steps sequentially in one checkout; concurrent generation can race on the same output directory. Independent checks that only read generated code may run in parallel.

## Bounded collection and analysis recovery

Terminal analysis maintenance must match failed jobs to queued analyses before applying its batch limit. A paused historical queue must not hide newer exhausted incremental jobs. Keep the per-row scope/job/candidate fences after selection; the isolated PostgreSQL regression covers more than one full batch of paused history.

Pixiv directory fallback details must pass the same future-window deferral as batch metadata. A future item written into a successful baseline can disappear permanently when its ID falls outside the bounded recheck prefix. Test a second window, including an initially empty `none` window, rather than only asserting the first page.

Pixiv profile resolution uses the native App API without enumerating works, but still needs the same rate-limit wait guard as collection. Native 300-second throttling sleeps must become `rate_limited` before the bounded profile subprocess times out; retain ordinary request pacing. ## Source management and credential updates

- Management history reads bounded summaries (default 10), then durable account tasks and scan/current-gap details on demand. Aggregate task and item counts separately before joining; a task×item join silently multiplies totals. PostgreSQL select-only parameters need explicit casts such as `::boolean` when their result type is part of the API contract. Legacy summaries do not reconstruct missing execution history.
- Current adapter health uses only the runtime available adapter and its enabled state; retired adapter failures belong to history. A later successful task is follow-up evidence, not proof that all gaps from an older run have been repaired. Complete and policy-excluded posts are different outcomes.
- A job attempt is a refundable budget, not an execution identity. Use job+lease for admitted execution records; keep business completion separate from confirmed child/stream/cleanup settlement, including optional profile avatar work. Lease expiry never settles an unknown owner.
- Credential input limits must agree across HTTP validation and file normalization before registering an unresolved operation. Failed preparation with no published material remains explicitly cancellable; a prepared or promoted result requires recovery under the same operation. Never regress a terminal receipt when a commit reply is lost. Resume rechecks the local credential fingerprint under the platform barrier before waking only maintenance-deferred work.
- Optional online editing assumes one shared writable private file view. Reject shared platform material and symlinks. Recover is read-only; promote replay re-syncs directories after a lost flush receipt. Native Windows mode bits cannot certify private ACLs, so online editing is read-only there. The externally confirmed stopped-owner CLI is an explicit operator attestation, not automatic process-exit proof or permission to clear queue state.
- Failure badges read execution evidence only when opened. Persist and revalidate bounded machine facts (recognized transport cause, exception, missing field, HTTP/size/format, operation and runtime); private journal sanitization is not an API response-body policy. Never infer an HTTP status or an exact cause from a generic historical summary, or fabricate execution history from journal lines.
- `journalctl -o json` may return a null MESSAGE for a long entry unless `--all` is supplied. Verify this output boundary before concluding that structured failure logs were not emitted; apply the private-data filter before displaying any log content.

## PostgreSQL runtime alignment

- Development, CI, production and backup/restore images target PostgreSQL 18. Its official image uses `PGDATA=/var/lib/postgresql/18/docker`; mount persistent volumes and temporary databases at `/var/lib/postgresql`. Keep the isolated image drill's client/server version, data directory and container-recreation checks aligned. Changing a major image tag is not a data upgrade: preserve old volumes and migrate into an independent target first.
- New encrypted backups carry PostgreSQL 18 metadata; readers still accept authenticated PostgreSQL 17 archives. Keep legacy-read coverage when advancing the writer, without treating archive compatibility as permission to restore a newer database into an older server.

## Registration and account qualifications

## 候选拆合入库与来源边界

- 普通逐帖重放不能冒认合并或拆分结果；特殊操作依赖发起人和操作标识的完整回执。查询不到回执不能清除不确定请求，重发仍使用同一意图。
- 主来源只是发布兼容摘要，完整来源必须通过显式关联读取。来源媒体授权只沿当前作品的直接来源，不沿共享来源跳到另一作品的其他帖子。
- 历史请求版本未知与图片映射未知是两件事，迁移不能根据空 revision 猜测图片是否采用。来源记录须区分另一作品采用和未采用。
- 原生 dialog 内的拖动浮层必须留在顶层弹窗中；整卡拖动要区分短点预览、独立按钮和兼容 click，草稿变更时取消旧拖动。浏览器拖动/自动滚动验证需将测试页置于前台，后台 rAF 节流不等于逻辑故障。

- Pointer capture 在取消时释放后，浏览器可能把同手势的兼容 click 发给 dialog 共同祖先；抑制范围须绑定手势和编辑器 root，延迟松开仍保护，新的 pointerdown 立即放行。键盘 click 不应被吞掉。
- 取消保护同样覆盖尚未达到拖动阈值的按压；正常短点仍可预览。拆合草稿按来源、版本和有序图片内容恢复，选择代际只用于结算；恢复时更新选择快照，成功后清理包含已处理来源的其他草稿，保留不相交草稿。
- 大量图片的拖动浮层坐标应直接更新 DOM ref，仅落点变化触发 React；缩略图复用稳定 props 的 memo 边界，保持签名 URL 按需读取。草稿和冻结请求是受离开保护的页面会话状态，不额外把来源资料写入 localStorage。
- 顶部操作栏保留横向滚动时，内部绝对定位提示会触发另一轴的自动滚动，导致按钮位移且提示被裁切。禁用原因复用现有 portal 提示；回归须包含真实 `.workspace-topbar-context`，同时检查悬浮前后坐标、窄屏横向滚动和键盘聚焦。
