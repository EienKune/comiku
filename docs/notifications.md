# 群通知

通知模块提供持久事件登记、QQ群目标与事件开关、消息预览、发送测试及投递处理。平台通过 OneBot v11 HTTP 主动调用 NapCat 等兼容实现，机器人继续由部署者管理；无需为了发通知再启动一个机器人框架。

作品核心流转通过已有持久 WorkEvent 异步接入。业务服务继续只执行原有业务与事件保存，不调用机器人或通知登记服务；通知后台在独立事务中补账、入队和投递。默认关闭，启用后从首次启动补账的持久起点接收新的受支持事件，不自动群发起点之前的历史。

认领仅表示加入翻译、校对或嵌字职责，不直接改变制作状态；首次实际编辑、嵌字交接和阶段提交分别形成开始与流转通知。运营通过发布权限确认发布，不是第四个可认领职责。审核是独立状态轴，不把“需要审核”当作固定制作步骤。

## 配置连接

默认关闭通知，不运行通知维护/消费循环，不请求机器人。API 和 worker 使用相同的私有配置；配置文件放在仓库和镜像构建上下文之外。

```dotenv
NOTIFICATIONS_ENABLED=true
NOTIFICATION_CONNECTIONS_FILE=/absolute/private/notification-connections.json
COMIKU_QQ_BOT_TOKEN=replace-in-private-environment
```

文件支持连接数组或 `{ "connections": [...] }`，最多 8 个连接、64 KiB。示例只包含占位地址和环境变量名称，不要在公开文件中填实际凭据。

```json
{
  "connections": [
    {
      "key": "team-qq",
      "name": "团队机器人",
      "adapter": "onebot-http",
      "endpoint": "http://127.0.0.1:3001",
      "tokenEnv": "COMIKU_QQ_BOT_TOKEN",
      "allowedIps": ["127.0.0.1"]
    }
  ]
}
```

连接文件只能由部署者维护，网页不接受任意 endpoint、headers、token 或 action。API 只返回连接名称和是否可用，不回显 URL、密钥或内部指纹。坏文件或某连接配置错误会使通知不可用，不触发机器人探测，也不会把私密解析错误传给业务接口。

HTTP 只允许显式许可的 loopback/私网地址；公网连接使用 HTTPS。DNS 返回的所有地址都必须在精确 allowedIps 内；请求固定连接经过验证的地址，不跟随重定向、不继承环境代理。metadata、链路本地、多播和未指定地址始终拒绝，HTTPS 使用正常证书验证。总超时 5 秒、响应最多 64 KiB，连接池随应用关闭释放。

连接配置按进程启动时读取。换 endpoint、token 或允许 IP 后，重启通知相关 API/worker 以采用新配置，再在系统管理中重新保存对应群目标，确认新的连接代次。旧投递不会自动改用新连接。先停用目标并等待在途请求结束，可使轮换边界更清晰；未确认的在途发送按未知结果处理。

## 系统管理

在系统管理的“推送通知”页签管理，分为群订阅、消息模板和投递记录。只有当前具有 system:manage 的用户可以读取通知配置和投递记录，或执行新增、修改、测试、核对及补发。每群选择连接、群号和事件；有持久职责的事件可以选择不限制职责或指定职责。未知职责只匹配不限制的规则，不按作品当前状态推断。新群默认停用、事件空选；启用必须选择事件。

15种业务事件各有一份公共结构化模板。作品标题、作者、操作人分别开关，默认均关闭；可以填写最多120个Unicode码点的纯文本提示语。固定的作品编号、事件动作、发生时间、可用的状态变化与完整站内链接保留。缺资料省略整行。草稿预览使用合成数据，不保存、不发送；没有任意字段路径、脚本或群专用正文编辑器。

保存模板只影响之后首次成功捕获的通知，不更改旧正文，不取消已登记的队列。模板内容修订、管理并发revision和群受众代次独立。旧群保持原详情开关，需明确预览并切换为事件模板；切换不改变受众代次或取消旧待发，新建群默认使用事件模板。

“发送样例”使用已保存群配置、指定事件和职责及合成资料，确认目标与正文后排队。保存配置和预览都不发送；返回排队不等于群内已收到。旧客户端不能用详情总开关覆盖已采用事件模板的配置。

图源采集与推送页签切换保留未保存草稿和展开状态，非激活面板暂停查询。连接“可用”表示本机配置通过校验，不表示机器人当前在线或群内可发送。

默认消息包含编号、动作、发生时间及需要登录的站内详情链接。额外内容使用固定白名单；不会把审核理由、内部备注、授权凭证、原图、签名 URL 或任意 WorkEvent.detail 发到群里。用户文字编码为 OneBot text 段，文字中的 CQ 码不会触发图片或 @全体。

停用、改群、连接或更改事件/职责订阅会推进受众代次，取消该群旧代全部未发送记录并保留原因，包括仍符合新订阅的消息；重新启用只接收新起点后匹配的事件，不倒灌历史。全局运行开关关闭则暂停后台处理并保留既有待办。已通过发送边界的在途请求仍可能完成，关闭开关无法召回已在网络中的消息。

原样保存不会生成新投递策略，仅修改群目标的显示名也不会取消待办。管理页面使用的 revision 与后台投递代次承担不同职责：前者防止多人覆盖编辑，后者控制是否允许继续向原受众发送。

## 事件登记接口

模块导出 NotificationPublisherService，供其他受控集成通过公开接口接入，不依赖机器人协议或群号。没有任意发布业务事件的管理 HTTP 端点。下列同事务接口仍可使用，但作品默认接入选择异步补账，不把通知写入作为作品提交成功的额外条件。

```ts
await publisher.recordTx(tx, {
  eventKey: `work-event:${sourceEventId}`,
  type: "stage_submitted",
  resourceId: workId,
  aggregateVersion: savedWorkRevision,
  ordinal: 0,
  occurredAt: occurredAt,
  workNumber: workNumber,
  stage: "translate",
  fromWorkflowStatus: "translating",
  toWorkflowStatus: "pending_proofread",
});
```

recordTx 只执行数据库查询和登记，可与业务提交原子保存；失败向调用方返回，不静默漏记。它保存登记时生效的群订阅与原目标快照，异步路由不按后来的群配置改写历史。相同 eventKey 与相同归一化数据返回原事件；同 key 的不同内容冲突。不要在业务重试时换新 key 或重新生成发生时间。

record(event) 在独立事务中登记，并对可重试的数据库事务冲突作有限重试。它不保证与之前另一个业务事务原子；业务已提交、进程在调用 record 前退出仍会漏事件。需要可靠关联时应使用 recordTx，或另行设计具备持久来源的补账流程，不能用 fire-and-forget 或扫描时间游标替代。

当前事件目录包括入库、认领/退出、开始编辑、嵌字交接、页码分工、阶段提交/取消、免校、审核申请/撤回/恢复、归档/恢复和发布确认。类型复用生成的 WorkEventAction；自动保存、逐图识别和作者变化不在此目录。直接调用方提供聚合版本与事务内 ordinal；同群同资源按已登记顺序处理，不承诺任意延迟外部登记仍能恢复全局因果顺序。

## 作品事件异步补账

原有业务事务已经保存 WorkEvent。通知后台反复查找受支持且尚未捕获的源行，每批最多 50 项，逐项在短事务中保存独立 receipt、安全输入及受众快照，同时更新源的捕获标记。另一短事务幂等创建 NotificationEvent 并将 receipt 标记为已登记。固定业务 key 为 `work-event:<sourceId>`，两处提交之间退出都能继续，无需重做作品操作。

未捕获集合有 partial index；不把随机 UUID 或 createdAt 高水位当成已消费进度。较早发生但较晚提交的源，只要属于持久起点之后，仍可被发现。首次 activation 起点持久保存，重启或全局暂停不会重置；起点之前的旧历史不自动补发。

登记阶段没有外部发送副作用，可恢复的数据库失败持久退避并继续重试，延迟上限五分钟。确定性坏输入、未知版本或 payload hash 冲突隔离并保留记录，不让一个作品阻塞其他作品。receipt 是通知内部账本，目前通过受控 ID 日志及数据库定位；管理页的投递记录从 Delivery 建立后开始，不提供独立 receipt 重试页面。

每个群的 sourceAcceptAfter 随真正的投递代次变化推进。旧积压在尚未捕获时遇到改群、停启或策略变更，可以保守跳过，不补给新受众；已捕获记录继续使用原快照并由现有投递代次门控。仅改名字或原样保存不改变起点。源时间只定义资格边界，不是精确提交时间，跨边界的长事务可能漏推。

现有 WorkEvent 没有历史 revision 或严格顺序号，桥接的 resourceOrdinal 表示捕获顺序，不能还原任意并发事务的业务因果顺序。消息使用源中持久化的动作、前后状态和发生时间；阶段仅白名单提取 detail.stage或事件明确的职责，作品编号来自稳定编号。

标题、作者名和原操作人展示名在首次成功捕获时读取并冻结，标注资料观察时点及capture_current来源。这表示补账时资料，不表示事件发生时名称；捕获失败回滚通知侧事务后重试，业务提交保持成功。后续登记、重试、补发不再读取当前资料。旧v1输入和正文保持原含义，不补入这些资料；同一事件投递旧群与新模板群时，各群独立冻结正文，不能把新资料串给旧模式群。不读取审核理由、备注、文件标识、签名地址或任意detail。

第一次捕获同时冻结该群匹配规则、模板完整设置与内容修订、群和连接代次及最终正文；捕获与管理保存通过数据库锁协调，避免拼出不同修订的设置。每个接收群有自己的内容快照。模板变更后积压仍使用原快照。

通知失败不会回滚已经提交的业务。源本身缺失、被删除或缺少历史事实，不能靠补账恢复；共享数据库仍有索引维护、异步标记和通知存储的有限开销。关闭通知时没有源扫描或机器人探测。

## 投递与故障恢复

后台使用既有 JobsService 的 network/notifications scope，独立于采集与图片处理槽。事件、投递和尝试是持久记录，Jobs 拥有执行租约；通知模块不另建一套租约引擎。短事务预约发送，提交后调用网络，再用条件写保存回执；网络期间不持业务或投递行锁。

| 状态       | 含义                                                      |
| ---------- | --------------------------------------------------------- |
| pending    | 已登记，等待执行                                          |
| sending    | 已跨越发送预约边界，外部请求可能发生                      |
| retry_wait | 已确定未发送的暂时故障，等待有限重试                      |
| accepted   | 协议返回成功且保存 message_id；不代表所有群成员收到或已读 |
| failed     | 永久拒绝或安全重试次数耗尽，记录保留待处理                |
| unknown    | 超时、断线、异步响应或发送后崩溃等，无法确认结果          |
| cancelled  | 用户停用/改群、权限或配置代次改变，未继续发送             |

同一业务 key、重复路由和多 worker 竞争不会重复建立普通投递。可确认尚未发出的暂时故障有限自动重试；unknown 不自动再发。已有 Job 第三次租约耗尽后可能不再进入 handler，因此维护循环还会有界对账，把遗留 sending 收敛为 unknown。

未知结果只隔离同群同资源的后续投递，其他作品继续。管理员可以标记已核对，或在明确接受可能重复后创建历史补发；原记录和尝试保留，补发操作有独立幂等 key。历史补发保留原正文并增加补发标记，不套用当前模板；新格式为标记预留预算，无法安全追加标记的旧长正文明确拒绝。受众已经改变时不能把历史补发给新群。测试与人工补发发送前重新检查发起人资格；团队业务通知不依赖旧配置人始终在职。

未决事件和投递不会因时间自动过期或清理。故障后应查看投递记录，处理 failed/unknown 或明确取消。当前不提供历史正文自动清理或摘要合并；规模增长后需增加安全保留/归档策略，不能删除去重证据后重新发送旧事件。

OneBot 标准不提供客户端发送幂等键。站内持久意图可以防丢记、防重复排队，但不能在远端已发、回执丢失时同时严格保证群内恰好收到一次。echo 只是请求关联标识。HTTP 200 仍需检查 status/retcode/message_id；async 不作为成功回执。参见 [v11 HTTP](https://github.com/botuniverse/onebot-11/blob/master/communication/http.md)、[消息 API](https://github.com/botuniverse/onebot-11/blob/master/api/public.md)。

## 验证与扩展

普通测试只使用合成事件和本机协议替身，不访问真实群。数据库测试要求独立 _test 数据库；迁移是追加式，并验证重复部署与无漂移。真实机器人验证应使用专用测试群，分别核对入队、协议回执和群内可见消息。

后台批量有界，外发串行、按群持久限流，关闭时不轮询通知。当前少数群无需 Redis、额外 Python 或完整机器人框架。适配器契约保留独立事件与传输结果，后续可实现 OneBot v12/其他平台、个人身份与 @、批次摘要或催办；每项需单独实现并验收，不在 UI 暴露未实现的平台入口。
