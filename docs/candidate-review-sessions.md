# Candidate review sessions

`POST /api/candidates/review-sessions` requires `candidates:read`. Supply an idempotency UUID and the list's base filters (`status`, `authorId`, `search`, `sourceLanguage`, `fetchedAfter`, `fetchedBefore`). Group, page size and cursor do not form the base filter. The response explicitly contains only `sessionId`, `expiresAt` and four group counts.

The server materializes candidate IDs, group and rank once with `INSERT SELECT`. Photo classification precedes blocked tags, which precede valid tags/current-model positive evidence, followed by neutral. Valid evidence is independent of aggregate completion; invalid, missing, duplicate-label and old-model caches cannot promote or rank a candidate. Current adapter taxonomy and review policy are parameters, not SQL identifiers.

Pass `reviewSessionId` and the same base filters to `GET /api/candidates`. All groups share the session; each group has its own opaque cursor. Members and ordering remain stable while cards, permissions, author archival and human review status remain current. Each request hydrates at most the requested page (maximum 100); total and pending-work metadata are computed in SQL. Session creation still sorts and stores the complete eligible membership and is not O(page).

Sessions expire after 30 idle minutes or two hours total. Reads renew at most once every five minutes. Model/filter changes produce 409; expired sessions produce 410. Signed v1 ordinal cursors bind session, filter, model and group; the per-session signing secret is stored only in the database and never returned. Cursors do not grant permission. Existing clients without a session use live SQL keyset pagination; old UUID cursors now receive an explicit 400 version error and must restart at the first page. Live mutable scores can still move across a keyset boundary; use a review session for stable review.

`replaceSessionId` atomically replaces an owned session only after the new snapshot succeeds. Creation and idempotency are serialized by actor. At most three active sessions are retained per actor; a fourth without a replacement evicts the least recently used session. More than 50,000 matching candidates produces an explicit narrowing error and rolls back the new snapshot and replacement. Worker maintenance deletes at most 2,000 expired entries and 20 empty sessions per minute; session deletion cannot cascade a large populated snapshot.

The web candidate scope creates one session shared by its four groups. Background analysis and source-sync completion rehydrate current cards. The compact **刷新列表** action replaces membership/rank, while **同步图源** retains its collection action. Selection stores candidate ID and the first observed revision across pages, replacement and expiry. Explicit base-filter changes clear selection. Bulk results remove only `succeeded` and `unchanged`; failed, conflicted and omitted results stay selected for inspection.

Integration fixtures require a separate `_test` PostgreSQL database and clean only their owned users/authors/candidates/sessions. Synthetic scale measurements should include snapshot sorting/materialization, 24-item hydration/JSON size and Node heap, ordinal-page plans and bounded cleanup at 1k/10k/50k. These measurements do not establish real-model or production throughput.
