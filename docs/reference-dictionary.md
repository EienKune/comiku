# 翻校参考词典与常用符号

翻校编辑器在 LabelPlus 工具旁提供“拟声词”和“符号”。词典用于理解效果音及寻找表达，成员结合画面决定实际汉化；查询不会自动修改译文，也不把参考资料当作强制术语表。

## 查询和编辑

具有作品读取权限的登录成员可以查询；首版不提供网页新增、修改或资料上传。打开弹窗并输入后才请求，约200毫秒防抖，每页20条；关闭或改变查询会取消旧请求。空查询不读取全部词库。

原文精确命中优先，其次匹配归一词形，最后匹配词形或解释中的文字；相同匹配等级优先显示有中文解释或汉化建议的记录。NFKC与片／平假名转换只用于检索，原始词形仍保留，清浊音、促音、长音及重复次数不被删除。同词不同义、不同资料的记录各自保留出处。

中文解释、日文说明与可空的汉化建议分开。没有汉化建议时不把整段解释冒充译词；复制也不会替换编辑草稿。来源URL和许可有值时显示，不返回开发者电脑的文件路径。

符号面板提供固定字符集合。有仍有效的译文输入目标和选择范围时，通过编辑器现有草稿与自动保存协议插入；目标丢失、换页或条目、无法编辑、标记未同步、IME组合等情况下回退到复制，不向旧输入框写入。浏览器不允许复制时显示可手动复制的字符。只读查看不因这个工具获得写权限。

## 数据和开发导入

`OnomatopoeiaSource`保存稳定来源key、资料版本、文件SHA256、解析/映射版本、导入revision和出处。`OnomatopoeiaEntry`保存原文、检索键、源记录位置及独立的中文解释、日文解释、汉化建议和备注。

词形及“词形＋汉化”不唯一。唯一约束是当前来源内的`(sourceId, sourceRef)`，用于保留同词的不同源记录。行号或单元格只是当前快照内的位置，不能当作跨版本的词条身份。开发补充的汉化应作为独立、可重放的来源，不直接填入下次升级会被替换的第三方快照。

首次运行先按项目说明安装依赖。准备工具和合成测试见[离线资料准备](../tools/onomatopoeia/README.md)；可选Python依赖不进入默认应用运行时。原始资料、人工映射、导入JSON及含释义的核对报告应保存在Git和Docker上下文之外，不随应用提供真实词库种子。

导入接受一份UTF-8 JSON快照。默认仅验证文件，不连接数据库、不启动应用、采集或通知任务：

```sh
pnpm dictionary:import /absolute/private/reference.json
```

确认清单后，在明确配置的目标数据库上显式执行。新来源的预期revision为0：

```sh
pnpm dictionary:import /absolute/private/reference.json --apply --expected-revision 0
```

已有来源必须传入已核对的当前revision。导入器先完整校验，再取得该来源的事务锁并重新检查revision；替换词条与更新来源元数据在同一事务中完成。失败回滚旧记录；同一文件与同一解析/映射版本重复导入返回`unchanged`。修复解析或人工映射后必须改变导入版本，即使原文件字节没有变化。输出仅含状态、数量和revision，不输出释义、连接串或凭据。

网络或提交回执丢失时，CLI不能证明事务是否已提交；成功提交后的连接清理也可能报错。遇到结果未确认，先只读核对来源revision与导入指纹，再决定是否按当前revision重试，不把报错直接等同于回滚：

```sql
SELECT key, revision, file_sha256, importer_version
FROM onomatopoeia_sources WHERE key = 'example-reference';
```

输入最大32MiB，单来源最多50,000条。多行解释可包含换行和制表符，其他控制字符、非法Unicode、重复源记录位置或超限字段会在写入前拒绝。来源URL仅允许不含用户凭据的HTTP(S)链接。普通测试使用合成数据和隔离的`_test`数据库，不读取开发者的真实词典资料。

应用代码与导入工具使用MIT，第三方资料保留自己的来源和许可。数据导入授权不自动等于公开再分发授权。运行时只查询本地数据库，不请求外部词典、不下载原始文件，也不增加定时采集任务。
