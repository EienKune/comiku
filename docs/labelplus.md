# LabelPlus 兼容规范

本文定义 Comiku 支持的 LabelPlus 文本子集及其与内部翻译条目的映射。业务规则仍以[架构说明](architecture.md)为准；本规范只约束文件解析、生成和兼容边界。

## 1. 编码与换行

- 导入接受带或不带 UTF-8 BOM 的 UTF-8 文本，拒绝无效 UTF-8 和空字节。
- 导出固定使用 UTF-8 BOM 和 CRLF，确保常用 LabelPlus 工作流可以直接读取。
- 接受的格式版本为 `1,0`。文件头完整保留在解析结果中；未知版本不能按 `1,0` 猜测解析。
- 单个文件限制为 2 MiB、2,000 个图片章节、20,000 个标记，单条译文限 100,000 字符。HTTP 上传层限制为单个文件、每文件 2 MiB；文件内容由解析器校验，不依赖文件名或客户端 MIME 声明。

## 2. 文件结构

文件由文件头、图片章节和图片内标记组成：

```text
1,0
-
框内
框外
-
...

>>>>>>>>[page-01.png]<<<<<<<<

----------------[1]----------------[0.250,0.375,1]
第一行译文
第二行译文
```

图片章节名必须非空，不能包含 `]` 或换行。没有标记的章节仍然保留，因此导入不能只按已有译文创建图片列表。重复图片名会产生警告，实际导入作品时必须先解决其与作品图片的歧义。

标记头包含展示序号、归一化 `x/y` 和标签类型：

- `x/y` 以图片左上角为原点，范围为 0–1，与浏览器缩放和原始像素尺寸无关。编辑器、导入持久化和规范导出统一保留三位小数；导入仍接受合法的更高精度坐标并在保存时四舍五入，兼容已有文件和本地草稿。
- 当前 `type=1` 映射内部 `inside`，`type=2` 映射 `outside`。其他整数先作为解析警告保留，不能在没有用户决定时映射成已知类型。
- 文件中的展示序号只用于兼容检查。内部持久化稳定 ID 与 `order_index`，导出时按图片内顺序重新生成从 1 开始的连续编号。
- 译文从标记头下一行持续到下一标记或图片章节，允许多行和内部空行。规范生成器在条目间加入一个空分隔行；解析器消费这一个分隔行，额外空行仍属于译文。
- 格式没有转义结构标记行的机制。译文如果完整等于图片章节或标记头格式，导出应拒绝并提示修改，避免再次导入时被误识别为结构。

## 3. 内部模型映射

| LabelPlus            | Comiku                                                         |
| -------------------- | -------------------------------------------------------------- |
| 图片章节顺序与文件名 | `work_images.order_index`；文件名由导入映射层匹配              |
| 标记顺序             | `translation_entries.order_index`                              |
| `x/y`                | `marker_x` / `marker_y`，数据库 Decimal(4,3) 并带 0–1 CHECK    |
| `type=1/2`           | `marker_position_type=inside/outside`                          |
| 标记正文             | `translated_text`                                              |
| LabelPlus 没有的备注 | `note`，导出时不写入正文                                       |
| 原始文件与解析警告   | `labelplus_files` 引用私有 `file_objects` 并保存 warnings JSON |
| 正式提交时的全部条目 | `translation_versions` 和不可变 `translation_version_entries`  |

当前草稿条目按条目携带 `revision`。创建请求使用图片范围内唯一的 idempotency key；图片内 `order_index` 唯一。正式版本独立复制坐标、类型、译文和备注，即使当前条目随后删除或修改，历史快照也不会变化。

## 4. 解析结果与警告

以下情况直接拒绝：无图片章节、无效 UTF-8、未知格式版本、坐标越界、结构行损坏、资源限制超出。以下情况返回警告，由导入流程在写库前呈现：

- 图片文件名重复；
- 文件内标记展示序号不连续；
- 标签类型不是当前支持的 1 或 2。

仓库 fixture [minimal.txt](../apps/server/test/fixtures/labelplus/minimal.txt) 是自行制作的脱敏样例，覆盖多图片、空章节、框内/框外、多行和内部空行。测试要求 `解析 → 规范导出 → 再解析` 的语义结果一致。不使用真实作者作品或工作文件作为测试输入。

## 5. 导入与导出流程

Codec 只负责文本格式，不读取数据库、不决定权限，也不把图片名自动猜测为作品图片。业务导入先解析预览，再由用户确认覆盖：

1. 文件章节按顺序与作品图片一一映射，预览同时展示来源章节名和目标文件名。
2. 章节数必须与作品图片数相同；重复章节名或未知标记类型会阻止导入，序号不连续只提示并按实际顺序归一。
3. 用户明确选择本次导入使用的翻译或校对参与职责。服务端在作品锁内重新解析映射并校验 work revision、editor epoch 和参与权限。
4. 导入原子替换全部当前草稿条目，各图片的 `translation_revision` 同步递增；随后保留原文件和警告、创建 `labelplus_import` 不可变版本、递增 work revision 与 editor epoch，并写入作品事件。事务失败时清理尚未被引用的文件对象。

导出读取已经保存到服务端的当前草稿，固定使用默认 `1,0` 文件头、UTF-8 BOM 和 CRLF。图片章节按作品编号与页序命名，例如 `7-001.png`、`7-002.jpg`；统一嵌字交接包中的原图使用相同名称，译文文件为 `7_翻译.txt`，位于同一目录。导出记录保存生成者、文件名、章节数、标记数和幂等键，下载再次按所属作品校验权限。浏览器仍有本地待同步内容时，前端不允许导入或导出。
