# 作品归档导出

管理员可以在“系统管理 → 数据导出”按作品入库月份导出文件，用于离线保存。月范围使用 `Asia/Shanghai`；年度任务仍按入库月组织作品，不按成图或发布月份重新分组。

## 导出内容

- **生肉**：作品实际入库的原图及页序，不包括同一候选帖中未入库的图片。有翻校正文时附一份 LabelPlus TXT。
- **熟肉**：当前采用的有效成图版本，不收集所有历史成图。当前采用的版本不一定已经发布，清单记录实际状态。
- **生肉＋熟肉**：同时包含上述内容，TXT 随生肉保存。

默认排除已归档和已舍弃作品，可分别勾选包含；挂起作品仍按其制作与审核状态参与筛选。

TXT 优先采用当前成图绑定的校对／来源文本版本，其次读取当前有效交接对应的版本；没有可信关联时保留当前已经保存的文字，并在清单注明未交接或关联未确认。有正文时生成 TXT，编码失败计入任务异常。导出保留作品现有制作、审核及发布状态。

归档目录以入库年月和稳定作品编号组织，生肉、熟肉分开；作品清单包含作者、标题、文件名、长度、SHA-256 和版本来源。TXT 中的图片名称与实际生肉名称一致。

## 生成、下载和删除

先预览作品与文件数量、预计大小，再登记后台任务。预览用于估算，后台准备时冻结本次文件与文字清单并记录捕获时间。年度任务逐月捕获，每个月保留各自的资料快照。

大范围导出分为多个独立 ZIP。优先将一部作品放在同一包，过大的作品按文件跨包，页序和目录保持不变；完整 TXT 与作品清单位于该作品的首个分包，其他包沿用同一作品目录。可分别解压 ZIP，将同一作品需要的包解压到同一目录后查看。图片保留原字节，不重新解码、识别或有损压缩。

关闭页面后后台任务继续执行。已完成包可以先下载；失败和重启恢复以包为单位，保留成功包，重新生成未完成包。任务列表与包／异常明细分页加载，仅活动页面轮询进度。

管理页的**归档生成限速**以 MiB/s 配置，初始值 `0` 表示不限速。它控制归档生成数据流，不限制浏览器从 R2 直接下载已经生成的包。调整设置保留版本校验，运行中的任务在下一次配置刷新后应用。

下载并核对后，可点击**删除导出文件**，勾选“已下载并核对”再确认。服务端验证管理员权限、任务版本与确认字段，然后异步清理该任务自己的 ZIP。只有任务结束后可以删除；运行中的任务需先取消并结束执行。

清理范围为本次管理员导出生成的 ZIP 和未完成上传；业务原图、成图、译文及导出记录继续保留。远端清理失败会显示原因并允许重试，清理完成后关闭下载入口。

归档包默认从任务结束后保留 **7 天**，到期由 worker 自动清理，按任务保留期执行，独立于下载与手动确认。通过 `ARCHIVE_EXPORT_RETENTION_DAYS` 调整保留天数。此规则用于“数据导出”生成的归档包，嵌字交接包和运营发布打包沿用各自的生命周期；需要时可重新创建归档任务。

## 部署与资源

功能默认关闭，API 与 worker 需使用一致配置。首版归档生成使用 R2；不配置可用归档存储时，不登记生成任务。开启后在同一 worker 使用独立 `heavy/archive:global` 单槽，不另起常驻进程；关闭时不启动归档轮询或 R2 客户端。

数据路径为 R2 源对象读流 → ZIP STORE 流 → 有界 multipart 上传 → 私有 R2 归档对象。服务器使用有界缓冲生成归档，归档与制作任务共享网络、CPU、内存和 R2 空间，部署时结合制作任务延迟调整资源预算与生成限速。

| 环境变量                            | 默认值          | 用途                               |
| ----------------------------------- | --------------- | ---------------------------------- |
| `ARCHIVE_EXPORT_ENABLED`            | `false`         | API／worker 同步启用               |
| `ARCHIVE_EXPORT_PACKAGE_BYTES`      | `2147483648`    | 每包目标 2 GiB；超大单文件另行成包 |
| `ARCHIVE_EXPORT_MAX_ENTRIES`        | `20000`         | 每包条目预算                       |
| `ARCHIVE_EXPORT_PART_BYTES`         | `16777216`      | 分片缓冲，允许 5–32 MiB            |
| `ARCHIVE_EXPORT_UPLOAD_CONCURRENCY` | `1`             | 上传并发，最多 2                   |
| `ARCHIVE_EXPORT_MAX_RUN_BYTES`      | `1099511627776` | 单任务源数据预算 1 TiB             |
| `ARCHIVE_EXPORT_CACHE_BYTES`        | `2199023255552` | 有效归档缓存预算 2 TiB             |
| `ARCHIVE_EXPORT_MAX_ACTIVE_RUNS`    | `1`             | 同时活动任务预算                   |
| `ARCHIVE_EXPORT_DEADLINE_HOURS`     | `72`            | 任务绝对运行期限                   |
| `ARCHIVE_EXPORT_RETENTION_DAYS`     | `7`             | 任务终态后的下载保留期             |

带宽保存在数据库配置中，由管理页修改，初始为不限速，不需要为此重启 worker。单任务预算不能大于总缓存预算；不支持无限缓冲或任意大临时盘。

归档缓存到期由应用按任务结束时间处理，R2 桶生命周期应保留仍在生成或可下载的归档对象；multipart 上传由应用结合任务回执恢复和清理。

## 恢复与校验

任务固定文件身份、原字节长度、SHA 和所选文本；源对象必须流式核对，不能只校验 ZIP 本身。文件清理会检查活动归档的引用，避免打包途中删除已冻结的源文件。

每次分包尝试使用独立对象 key，保存上传、完成意图及校验回执。完成响应丢失时先核对同一次尝试的对象，不把未知结果当作可以覆盖重传。租约过期不证明旧进程已经停止；未知执行保留必要引用和回执，进入待恢复状态，不按超时盲目删除。

正常停止会等待在途读取和上传结束；进程被强制结束后，管理员需独立确认对应物理进程已经停止，等待租约到期，再在同版本运行环境执行以下命令。owner UUID 从该任务的 `archive_export_attempts.owner_id` 查得，管理员 UUID 必须仍具备系统管理权限。该操作记录审计，只解除未知执行阻塞，随后 worker 核对已保存的完成回执，不能把“失去心跳”代替进程停止确认。

```sh
node dist/ops/archive-exports.js <owner-uuid> <administrator-uuid> owner_process_stopped
```

作品文件归档用于离线查看与保存，下载后由管理员核对文件完整性。数据库灾备及恢复按[部署文档](deployment.md)执行。
