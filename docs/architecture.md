# 业务与架构

本文描述 v0.9.0 的业务规则和系统架构。详细字段和接口以 Prisma schema、服务端策略和 [OpenAPI](api/openapi.json) 为准；UI 以 [DESIGN](../DESIGN.md) 和 Playground 为准。

## 模块与数据

React 前端使用共享 OpenAPI 客户端访问 NestJS。PostgreSQL 保存账号、作者、候选、作品、译文、版本、事件和任务；文件正文存于开发 local 或生产私有 R2，数据库只记录文件元信息、摘要、引用与生命周期。

API 处理认证、权限、短事务和任务登记；独立 worker 通过 PostgreSQL 租约执行网络及图片/ZIP 工作。网络与重任务分别有一个全局执行槽，重任务总并发为 1；租约支持进程退出后恢复，有限重试不自动改变作品流程。健康心跳只代表进程/数据库状态，不保证每个任务成功。

业务模块通过公开服务和契约协作，不直接依赖其他模块的内部实现。X、文件存储、LabelPlus、分类器通过适配器隔离；测试替身不调用真实 X/R2。

## 账号、角色与署名

- 账号由管理员发放；账户名仅用于登录，成员昵称用于界面和默认署名。用户可改密和头像，管理员敏感操作需验证当前管理员密码。
- 用户可拥有图源、翻译、校对、嵌字、运营、审核和管理员等多个职务。管理员不自动获得制作资格；主动接取仍需相应职务及语言能力，不代其他成员分配制作任务。
- 作者和作品各有一种来源语言，用户可以有多种语言能力。日语/韩语翻译、校对需对应能力；英语不单列能力授权，翻译或嵌字职务可接英语翻译，校对仍需校对职务。嵌字和运营不按翻译语言筛选。
- 默认作品为单人模式，每个制作职责只有一名参与者，同一用户不可同时参与该作品翻译和校对；可以兼任翻译与嵌字。管理员可显式开启多人协作，多人作品的分工与互相校对按协作约定执行。
- 临时署名以 `(work_id, user_id, stage)` 独立保存，发布前由本人修改；留空用成员昵称。取消一个职责只清理该职责的临时署名。阶段提交保留审计快照，最终发布冻结届时署名。

系统管理独立于个人设置，仅管理员拥有 `system:manage`。采集运行历史在管理入口查询；图源老师仍管理作者、授权与手动同步等业务操作。

## 图源与候选

授权作者包括昵称、母语、头像、标签、授权状态与图片凭证。凭证仅图源/管理员可查看；每位作者的 X、Pixiv 各最多一个有效账号。X 使用 handle 生成主页链接，Pixiv 使用数字用户 ID；多账号作者可建立独立作者记录。作者 CSV 先解析预览后原子确认，图片凭证单独补充。

X 两通道共用来源契约，游标、水位和健康按账号/适配器独立保存。错误响应不能被当作空页，失败不越过安全水位；官方回退受预算约束。可选 gallery-dl adapter 提供 X/Pixiv 作品抓取，其 Python 桥和固定依赖与 TS adapter 放在同一目录。作者管理根据可用 adapter 能力开放 Pixiv 采集；未配置时仍可只保存资料和主页。各实现的目录、构建资源和运行记录见[采集 adapter 说明](adapters/source-ingestion.md)。

图片识别由独立的持久 heavy 任务执行，依赖通用 `ImageAnalysisAdapter`；各 adapter 声明自己的类别集合，支持二分类及多分类，并输出独立排序分数。公开 example 使用 `comic/comic_related/other`，BA adapter 保留原生 `ba_art/ba_related/other`（BA 漫画／插画、BA 相关、其他），默认不启用识别。BA 实现与可选推理代码公开，权重、分类头和凭据由部署者单独提供，详见[接口说明](adapters/image-analysis.md)。逐图结果保存完整模型/预处理/类别身份和原图摘要，失败可重试，识别不改变人工审核状态。

手动上传的独立图片各为一个候选组；每个 ZIP 为一个组，目录只做有限两层处理，拒绝嵌套压缩包和越界路径。明确数字尾号按数字排序，否则沿输入顺序，图源可调整页序。可选择直接入库或进入候选；直接入库仍经过可追溯候选和文件校验。

候选保留有效标签漫画/插画、普通漫画/插画、黑名单标签漫画/插画、照片分组；组内先按已完成识别的排序分数，再按时间。优先组接受配置的有效标签或当前完整模型结果满足 adapter 的审核策略；BA 策略为至少一张图预测 `ba_art` 且该类置信度 ≥0.5。模型命中不会伪造原帖标签或修改人工审核，人工／既有照片分类与黑名单优先。BA 相关、其他及低置信度暂留普通组。分类置信度与排序分数分别使用；模型未启用时保持未识别，失败也不会伪造 `other` 结果。识别完成后，页面协调刷新各组，避免候选跨组移动时暂时消失。

作品入库生成稳定数字编号，舍弃后也不回收。作品标题和发布正文可以后续填写；原帖配文只作为参考，不自动填入发布正文。

## 制作流程和权限边界

认领、事实开始、提交是不同动作。成员可在上游尚未完成时提前认领，但不能越过工作阶段编辑。翻译/校对第一次实际内容变更才标记开始；只查看或空保存不标记。校对允许确认无改动直接提交。

提交产生不可变版本并切换编辑 epoch。需要修改已提交内容时，先明确取消提交：翻译仅在校对未事实开始时允许；校对仅在嵌字尚未取得有效交接材料时允许。不能通过取消认领抹去已经提交的贡献。未提交者可退出；最后一名翻译退出且有草稿时，需确认后清理当前翻译草稿并重置编辑边界，历史审计保留。

未认领或不具备当前编辑资格时工作区只读，服务端也拒绝写入。多人协作用页码分工和个人完成确认，更新按页合并，不将整组旧内容覆盖他人页面；仍校验 revision/epoch，不能跨提交边界自动套用旧草稿。

免校对是管理员授予用户的独立资格。单人翻译正式提交后可显式跳过校对；已经事实开始的校对不能跳过。已有但未开始的校对认领需要确认后清除；不生成校对署名。多人翻译不免校。嵌字交付前可取消翻译提交，交付后上游冻结；发布文案省略免校作品的整行校对署名。

## 编辑器和版本

编辑器使用图片归一化坐标，标点保留三位小数；新增追加、删除后连续编号。默认工具为移动画布，显式保留添加框内/框外和移动标记。Alt＋滚轮在图片区域按指针中心缩放；连续标点 Ctrl＋Z 仅撤销本次连续添加，切工具、换页、进入文本输入或失焦即结束该撤销上下文。

云端自动保存延迟 3000ms，并有主动保存按钮；本地草稿保留 7 天。打开工作区时核对服务器版本/epoch：内容不一致时由用户处理本地/云端选择，旧设备草稿不得自动跨越提交边界。离开时准确提示未同步内容，不将浏览器本地保存声称为云端完成。

翻译与校对分别保存最终版本，便于追踪差异。LabelPlus 的导入预览、图片映射和原子采用见 [兼容规范](labelplus.md)；导入也建立版本与新 epoch，不直接覆盖历史。

## 嵌字交接、成图和发布

后台生成的嵌字交接 ZIP 同时包含原图和 LabelPlus 文本。生成、查询、清单预览不冻结上游；明确交付时重新检查权限、审核状态和版本，成功签发下载才建立边界，失败不推进，重复交付不重复切换 epoch。

成图允许改变分辨率、数量及增加说明页，仍保留格式、单版 100 张和容量安全限制。单作品上传只保存版本；批量上传先按编号匹配、合并重复项并检查页序，最终确认按作品独立保存并提交嵌字。旧版本保留，删除/恢复有可审计语义，不能借恢复自动重新认领。

运营选择有效成图，编辑可选标题/正文，整理作者和翻校嵌署名，记录发布信息。空正文不产生额外正文空行。发布是运营动作，不是第四个认领职责；不自动发帖到 X 或其他平台。已发布快照不可变。

## 内容审核

成员因原作品内容是否符合团队规则而申请内容审核，填写理由后制作暂停，成员、成果和原阶段保留。申请人可撤销未处理请求；管理员确认继续或舍弃，舍弃后保留恢复入口。继续/撤销按原进度恢复，不重做流程、不额外解锁原本已冻结的上游内容。

审核与普通工作版本均保持单调 revision/epoch 校验。旧请求和上传预览在边界变化后需重新检查，不自动重放。内容审核机制聚焦于制作可行性决策（继续制作或终止舍弃），不引入复杂的分支返工流程。所有操作与权限均由当前业务契约和服务端策略严格约束。

## 列表、预览与私有文件

工作台展示个人待办和推荐接取。作品页默认工作视图“我的待办”，按实际资格提供可接翻译/校对/嵌字和运营待发布入口；查看视图展示全部阶段。可接任务先立即可做、后提前认领，组内编号倒序。服务端负责资格、总数与每批 24 项游标分页；切视角/筛选清空批量选择。

列表优先使用后台生成的长边最多 800px、质量 82 WebP 缩略图，只缩小不放大，原图小或收益不足时复用原件。大图按需读取原图，翻校及导出保留原字节。大图支持缩放平移，普通卡片图片以外区域进入作品详情。

原图、缩略图、头像、凭证和成图继承所属资源权限。预签名 URL 短期有效，知晓对象 key 不等于拥有读取权限。删除和清理按引用与恢复窗口执行，不统一删除历史对象。数据库备份不包含图片正文，恢复需要同时确保对象仍存在。
