# Comiku

Comiku 是基于 React + Vite、NestJS 和 TypeScript 构建的，面向小型漫画汉化团队的自托管协作系统。**v0.9.0 · MIT**。

Comiku 将「授权作者管理 → 图源候选 → 翻译校对 → 外部嵌字交接 → 成图管理与发布整理」串联在同一套工作流中。团队成员可身兼多职，通过个人待办与作品工作视图高效协同。

## 核心功能

- **成员与权限**：管理员分发账号，也可在账号管理开启自主注册，分别控制注册时能否自选业务职务与语言；注册后的资格由管理员调整，未完成认领的必要资格受到保护。支持自定义昵称、头像及修改密码。
- **授权与图源**：维护授权作者目录与授权凭证，关联 X / Pixiv 账号并支持 CSV 批量导入；支持单图、多图及 ZIP 手动上传，提供候选筛选排序、作品编号与批量入库。
- **任务调度**：提供工作视图、个人待办、推荐接取与批量认领；支持内容审核与可恢复舍弃。
- **翻译与校对**：内置图片标点、翻译与校对工作台；支持自动/主动云端保存、本地草稿恢复与不可变提交版本；支持单人职责约束、可选多人协作，以及按作品和职责独立保存的临时署名。
- **嵌字与交接**：兼容 LabelPlus 导入导出，后台自动打包统一的嵌字交接包，支持批量下载与成图上传提交。
- **成图与发布**：管理多版本成图，整理发布正文与人员署名，生成不可变发布快照及业务流水记录。
- **作品整理与检索**：按作者建立作品系列，维护章节和顺序；查看视图支持相册，候选大图预览可查询已入库作品中的相同文件与相似图片。
- **群通知与提醒**：通过 OneBot v11 HTTP 接入 QQ 群，订阅作品流转通知、每日工作摘要、提前认领的任务交接提醒和累计可制作 72 小时未交稿提醒。
- **可选角色生日**：工作台展示生日摘要和日历，支持群生日提醒；默认提供 BA 数据实现，其他团队可在代码装配处替换数据适配器。
- **界面与体验**：支持缩略图浏览、原图缩放平移预览，内置可换品牌色的柔彩/极简双主题及 UI Playground。

## 运行说明

Comiku 以源码形式分发，版本变化见 [CHANGELOG](CHANGELOG.md)。外部采集、图像分类、群通知和角色生日均按需启用：

- **外部采集**：使用配置了凭据的 gallery-dl X / Pixiv 适配器，自动抓取默认关闭。gallery-dl 需安装 Python 依赖并配置凭据，容器部署可选用 `gallery-runtime` 镜像目标。启用前在目标环境验证账号访问和采集结果。
- **可选图像分类**：分类默认关闭；已提供 BA PixAI 实现，模型权重与推理服务需单独配置。其他团队可通过 `ImageAnalysisAdapter` 接入自己的二分类或多分类实现，并配置类别展示与审核映射。后端结合逐图分类结果和原帖标签规则，将候选分为优先审核、待判断、低优先级；成员决定入库或忽略。切换实现需同步 API 与 worker 配置，并按[受控激活流程](docs/adapters/image-analysis.md)排空和激活后重启。
- **群通知与生日**：部署开关默认关闭，API 与 worker 使用一致配置。管理员分别管理作品事件、工作提醒和生日订阅；生日展示可独立于群提醒启用。
- **制作与发布**：嵌字在外部工具中完成，Comiku 提供交接包与成图管理；发布整理生成文案和快照，供运营发布。
- **部署验证**：站内核心流程、Linux 容器镜像及隔离备份恢复已有自动验证；外部服务连通性、生产容量和长期运行按目标环境验证。

## 本地快速启动

**环境要求**：Node.js **24.22.1**、pnpm **9.1.2**、PostgreSQL **18** 以及可运行 Linux 容器的 Docker。开发 Compose 提供 PostgreSQL 18。

_（注：若仅查看 UI Playground 则无需数据库，安装依赖后直接运行 `pnpm dev:web` 即可。）_

### 1. 初始化配置

先把根目录 `.env.example` 复制为 `.env`，不要覆盖已有配置：

- 检查数据库端口是否空闲；调整 `POSTGRES_PORT` 时需同步修改 `DATABASE_URL`。
- 如需在同一宿主机部署或开发多个实例，可在 `.env` 中指定独立的 `COMPOSE_PROJECT_NAME`（例如 `comiku-v09`）与数据库端口，避免共用 Compose 容器和数据卷。

### 2. 启动服务

```sh
pnpm install --frozen-lockfile
docker compose -f docker-compose.dev.yml up -d --wait postgres
pnpm db:deploy

# 首次启动，在交互终端创建管理员
pnpm admin:init

# 同时启动 Vite、API 和 worker
pnpm dev
```

- **默认浏览器入口**：<http://localhost:5173>（UI Playground：<http://localhost:5173/playground>）
- **开发 API 文档**：<http://localhost:3000/api/docs>（`/api/health/ready` 验证数据库连接，但不代替迁移检查）

### 3. 账号与日常维护

- **账号管理**：默认由管理员创建账号，也可在“系统管理 → 账号管理”开启自主注册，并选择是否允许注册时自选业务职责和语言。关闭自选时，新成员注册后由管理员分配资格。管理员创建账号时返回一次性临时密码，首次登录需改密；自主注册使用本人设置的密码。忘记管理员密码时，在本机交互终端执行 `pnpm admin:recover`。
- **更新代码后**：请先停止 API/worker，依次执行 `pnpm install --frozen-lockfile`、`pnpm db:deploy`，再启动 `pnpm dev`。**API 不自动应用迁移**；遗漏迁移可能造成详情页服务器错误。不得通过清库或删卷解决迁移遗漏。

### 4. 可选演示数据

在专用、可丢弃的本地数据库中执行 `pnpm demo:init`，可创建演示成员、校对成员、作者及单图/三图候选。命令会显示登录信息。示例图片由项目自有几何 SVG 生成，源文件与再生成命令 `pnpm demo:image` 一并提供。

> **⚠️ 警告**：**这个命令会清空现有作品和候选及其关联数据，并重置演示账号。** 它仅允许本机 `development` 数据库和 `local` 存储；**请勿在包含有效数据的数据库上执行**，日常启动无需运行此命令。

## 配置与部署

- **存储与密钥安全**：默认使用 PostgreSQL 和项目目录内的私有 `local` 存储，不需要 X/R2 凭据。生产模式要求私有 R2。所有密钥只放服务端环境文件，严禁放入 `VITE_*`、浏览器、日志或 Git。
- **生产部署模板**：仓库提供 `Pages + Caddy + API/worker + PostgreSQL + R2` 的部署模板，以及加密备份/隔离恢复工具。模板需要填写域名、数据库独立密码、证书、Bucket 和备份政策，不能直接以示例参数上线。

## 路线图 (Roadmap)

- [ ] **多源抓取与同步完善**：在现有 X 适配器和 gallery-dl X / Pixiv 实现上，继续完善覆盖范围、限流与中断恢复，并积累实际环境验证。
- [ ] **智能图源预分类**：在现有可替换分类接口与 BA PixAI 实现上，继续拓展通用分类器，验证分类质量、排序与审核分组效果。
- [ ] **界面交互与体验演进**：持续优化高密度工作台交互与标点操作流畅度；改善移动端浏览与轻量审核体验；支持账号级个性化偏好与主题持久化。
- [ ] **多渠道一键自动发布**：在现有不可变发布快照机制上，接入社交平台 API / Webhook 适配器，支持一键将成图与文案分发至指定平台或频道。
- [ ] **多模态大模型（MLLM）辅助翻译**：结合图片坐标打点与画框选区，接入多模态视觉大模型，实现文本框自动识别、语境辅助翻译与智能草稿预填。
- [ ] **更多通知渠道**：在现有 OneBot 群通知、工作提醒和生日提醒基础上，接入其他协作平台的消息投递适配器。
